# Geological evolution and compilation

- Existing owners: `terrain_impacts::ImpactField` owns impact records and crater process channels; `terrain_bake::TerrainBakeService` owns background bake lifetime and atomic activation; `AnalyticTerrainSource` and `GlobalTerrainFields` own canonical terrain sampling; `terrain_material_column` owns physical loose-material and substrate channels; `celestial_small_bodies` owns derived irregular-body appearance.
- Extend those owners with a chronological, spatially indexed geological event field and compiled planet bake products. Keep authored events and recipes as authority; sampled/baked elevation, age, fracture, material and ejecta fields remain disposable derived data. `ImpactField` owns a single candidate-ordered event composition over crater, connected-resurfacing and tectonic-renewal records; its spatial query emits all three categories into one stable age/ID merge before per-sample material and relief updates. `ChronologicalEvents()` and `EventsIntersectingCap()` expose stable references into those same canonical arrays, allowing regional compilers to obtain chronologically ordered tile-local batches without scanning unrelated global records. Authored `TectonicRenewal` slip events advect older impact centers through the historical sequence; `plate_motion=true` uses a closed spherical boundary to move all earlier impact structures on that regional plate. These episodes share the canonical geology event type and compiler; the existing analytic plate model remains the present-day tectonic source and does not synthesize a geologic time series automatically.
- The impact module compiles at the existing AnalyticTerrainSource seam and changes its source revision. It samples connected resurfacing polylines, chronology and material cover; M08 receives deposited cover in loose debris. Chronological impact and ice relief plus their material, age and damage channels compile into immutable cube-face scale-space rasters. Full raster compilation and local influence-cap rebakes distribute 32-by-32 tiles across up to eight workers with per-worker reusable spatial-query scratch, disjoint output writes, cancellation and progress accounting; full compiles query impact/resurfacing and fracture hierarchies once per tile, while local rebakes count only texels actually resampled. `ImpactField::EventsIntersectingCap` and `CollectEventsIntersectingCap` expose reusable chronologically sorted regional event batches from the same spherical hierarchies, `PreparedImpactGeometries` shares event frames/profile coefficients with regional compiler consumers, and `IceFractureField::CollectSegmentsIntersectingCap` extracts relevant fracture curves from its existing hierarchy. The bake file persists these fields as independently checksummed, losslessly zero-run-compressed cube-face regional tiles with one-texel halos; loading reassembles the exact canonical raster so CPU/GPU consumers keep one sampling authority. CPU terrain sampling consumes these process channels without walking the event indexes. The bake service reports the last geology raster sample count, participating event-record count and sample throughput. When authored crater or connected-flow records change alone, it resamples the union of their old and new influence caps into the existing base raster; global population, age, environment or fracture changes trigger a full compile. `ImpactField` merges local crater, resurfacing and tectonic-renewal candidates by age and stable ID before composing relief/material/age, so old deposits are excavated, younger flows bury older terrain, and later fault belts reactivate old structures.
- Expose edits through the existing terrain authoring model, command/RPC seam and dedicated MCP tools; UI and MCP must call the same operations.
- Studio injects `terrain_gpu::GpuGeologyCompiler` into `TerrainBakeService`: CPU code resolves and spatially batches canonical events once per tile, the compute kernel evaluates chronological impact/resurfacing and indexed ice-fracture batches into GEO1 base rasters, and the shared raster builder derives scale-space levels before activation. Stable-ID local crater/flow edits use the bounded regional path; tectonic slip edits trigger a full geology rebuild because they can move older features. Bake status includes samples/event throughput, invalidated tiles, dispatches, explicit GPU buffer transfers, fence waits and timestamp duration when available. The 1,000-overlap stress case emits a per-sample measurement, and the existing ten-million-population case checks bounded explicit storage plus deterministic statistical residuals. Debug and inspection: `OrbitStudio` and the affected targets compile; 14 focused geology, Vulkan parity, authoring, bake, lifecycle and seam tests pass in the current pass (21 broader feature tests passed before the direct Vulkan shader-parity test was added). The Vulkan test checks CPU/GPU relief, fracture and process channels over all six cube faces. The Windows tests need `TEMP`/`TMP` pointed at the writable workspace because the sandbox's packaged temp directory denies the atomic manifest rename. The debug pass fixed duplicate resurfacing-index node accumulation and fracture-cap queries that omitted the requested cap radius; CPU and GPU now share a four-width finite fracture support. No placeholder markers remain in the inspected feature files.
- Do not duplicate tectonic authority, place per-impact noise stacks in shaders, resimulate planetary history during render frames, or invalidate the entire planet for local events.
