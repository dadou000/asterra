# Orbit V0.0.4 — M01 Surface Coordinate and Sampling Contract

Status: **implemented**

Branch: `orbit`

Completed: 2026-09-17

M01 freezes the coordinate contract used by terrain generation, terrain caches, hydrology, erosion and derived regional terrain. Physical terrain identity is expressed in planet/body space. Cube faces, clipmap rings, render patches and GPU cache slots are projections or residency details and are not physical coordinates.

## 1. Canonical physical position

The permanent terrain-process coordinate is:

```cpp
struct PlanetSurfacePosition
{
    world::PlanetId planet;
    math::Double3 unitDirection;
    f64 radialOffsetMeters;
};
```

Rules:

- `planet` is stable authored/runtime body identity;
- `unitDirection` is normalized body-space direction from the planet center;
- `radialOffsetMeters` is measured from the reference surface;
- no cube face, tile, clipmap ring, viewport, frame number or GPU slot participates in physical position identity;
- cross-planet local-coordinate conversion is rejected rather than silently aliasing two bodies.

`CanonicalizeSurfacePosition` normalizes valid directions and sanitizes non-finite radial offsets. `SurfacePositionFromCube` exists only as a projection-to-physical conversion at storage/page boundaries.

## 2. Tangent frame

`world::SurfaceFrame` remains the common tangent basis:

```text
East  ─┐
North ─┼─ tangent plane
Up    ─┘  canonical body-space surface normal
```

`SurfaceTangentFrame` creates the deterministic default basis at a canonical position.

`AlignSurfaceTangentFrame` transports an existing regional/authored tangent orientation onto the canonical position before offset evaluation. This matters for hydrology and authored/process regions: migrating to the M01 coordinate contract does not rotate an existing local region.

Forward and inverse physical-meter transforms are provided by:

```cpp
OffsetSurfacePosition(...)
SurfaceOffsetBetweenPositions(...)
```

They operate geodesically on the planet reference sphere and preserve the regional tangent orientation supplied by the caller.

## 3. LOD-aware sample footprint

Terrain resolution is represented in physical units:

```cpp
struct TerrainSampleFootprint
{
    f64 diameterMeters;
};
```

The minimum safely resolvable procedural wavelength is currently defined as approximately twice the sample footprint:

```text
minimum resolved wavelength = 2 × footprint diameter
```

This contract deliberately contains no clipmap LOD number. A process can therefore make the same frequency-cutoff decision regardless of which render ring requested the physical sample.

`TerrainQuery` remains source-compatible with existing callers but now carries:

- canonical `PlanetId`;
- body-space direction;
- radial offset;
- physical sample footprint.

`MakeTerrainQuery` is the canonical construction path from `PlanetSurfacePosition + TerrainSampleFootprint`.

## 4. Cube-face and clipmap seam rule

Physical sampling is continuous in body space. Cube faces are storage projections.

At exact cube edges or corners, the same physical direction is valid on every sharing face. `ProjectDirectionToCubeFace` projects a body-space direction onto a requested page face rather than selecting one arbitrary major-axis face first.

Consequences:

- adjacent pages can independently sample their shared edge and receive the same physical input;
- three pages sharing a cube corner can all evaluate the identical physical point;
- a major-axis tie cannot introduce a face-dependent terrain phase;
- clipmap/ring selection cannot alter the physical identity or deterministic seed of a terrain sample.

## 5. Terrain cache integration

`TerrainPageBuilder` converts page grid coordinates to `PlanetSurfacePosition` before calling a terrain source.

`CachedTerrainSource` is bound to one `PlanetDefinition` and performs the following boundary normalization:

```text
incoming query
    ↓
validate direction + physical footprint
    ↓
resolve/verify PlanetId
    ↓
canonical PlanetSurfacePosition
    ↓
physical page selection
    ↓
cache hit ───────→ sample canonical direction
    │
    └ cache miss → canonical authoritative fallback
```

Legacy callers that omit `PlanetId` are upgraded to the cache-bound planet. An explicitly different valid `PlanetId` cannot alias the bound planet's physical cache pages.

Camera/view state remains absent from page identity and generation revisions.

## 6. Terrain-process integration

### Hydrology

`HydrologyGrid` now stores:

```cpp
terrain::PlanetSurfacePosition origin;
world::SurfaceFrame surfaceFrame;
```

Every grid cell is converted from its local meter offset to a canonical planet position before terrain sampling. Depression conditioning and D8 routing remain local-grid algorithms; their input samples now have stable physical identity.

### Regional erosion

`RegionalElevationDeltaField` stores the canonical origin inherited from its hydrology grid. Runtime sampling converts the canonical query position back into the field's oriented local meter coordinates using `SurfaceOffsetBetweenPositions`.

### River carving

`RiverCarvingField` has a canonical origin slot and the river-carved terrain source uses canonical planet positions for world-to-region conversion. Legacy fields without a populated origin are upgraded from their tangent-frame center and the bound planet rather than changing their generated layout.

### Derived terrain regions

`DerivedRegionTerrainSource` canonicalizes the incoming terrain query once and uses that same `PlanetSurfacePosition` and physical footprint for coarse regions, fine regions, river carving and lake sampling. This removes a separate direction-only world-to-region path.

## 7. Acceptance tests

M01 is covered by the following tests:

- `Orbit.TerrainContracts`
  - canonical position/query transport;
  - physical-meter footprint;
  - tangent-frame orthogonality;
  - geodesic local-offset round trip;
  - cross-planet alias rejection;
  - physical page identity independent from camera/view state.
- `Orbit.TerrainFaceSeams`
  - two-face exact edge equivalence;
  - three-face exact corner equivalence.
- `Orbit.TerrainM01Integration`
  - legacy cache fallback acquires the correct planet identity;
  - generated adjacent terrain pages agree at one physical seam sample;
  - hydrology and regional erosion retain the same canonical origin.
- `Orbit.TerrainHydrology`
  - hydrology emits normalized, planet-identified terrain queries while preserving existing routing/depression behavior.

Existing terrain cache, region and erosion tests remain regression coverage for compatibility with the V0.0.3 runtime.

## 8. M01 invariants

The frozen M01 rules are:

1. **One physical location has one body-space identity.**
2. **A cube face is not a terrain-generation coordinate system.**
3. **A clipmap ring is not a terrain-generation coordinate system.**
4. **LOD is communicated as physical sample footprint, not render-level identity.**
5. **Terrain-process local planes must retain a canonical planet-space origin.**
6. **Cross-body coordinates may not alias.**
7. **Moving the camera may change requested residency, never generated physical identity.**

## 9. Boundary of this milestone

M01 establishes where terrain is sampled, not what the terrain is made of.

The next mandatory milestone is **M02 — Geological Material Library**, which introduces the authored physical rock/material records consumed by the geology and terrain-process layers.
