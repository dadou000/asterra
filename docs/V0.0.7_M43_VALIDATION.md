# Orbit V0.0.7 M43 Validation Matrix

M43 deliberately separates two kinds of evidence:

1. **Deterministic numerical gates** run without claiming GPU image determinism. They pin physical/semantic invariants using the same production math and services used by Orbit.
2. **GPU visual-tolerance captures** exercise the production Vulkan renderer on named hardware. They may use tolerance bands and temporal warm-up, but may not replace the underlying lighting, volume, cache, or presentation implementation with test-only code.

The Studio-facing setup is exposed through the ordinary `Explorer` context command surface under the `Validation / V0.0.7` command category. The normal `VolumeAuthoringUi` owns the registration. Scenario preparation uses `CommandService`, the existing authoring command registry, `StudioViewportRenderer`, the lighting runtime policy, and the native volume-cache pipeline.

## Deterministic executable

CTest target:

`Orbit.V007DeterministicValidation`

It covers the M43 catalog plus physical emissive authority, eye ceiling/overload recovery, dark-to-light recovery, RT budget independence, 2.5D and local-3D reference transport, emissive volume integration, native cache determinism, and representation blend/stable-address invariants.

## GPU capture rules

GPU evidence must record the scenario name, Orbit commit, GPU/driver, Vulkan capability set, ray-query availability and policy, viewport/output mode, lighting budget, volume solver/render budgets, warm-up frame count, and capture frame. A visual comparison must identify its metric/tolerance rather than requiring byte-identical images.

M43 does **not** treat a CPU invariant pass as proof that the GPU renderer is correct. Windows/Vulkan build, validation-layer, image-tolerance and real-device execution remain separate release evidence and feed directly into M44/M46.
