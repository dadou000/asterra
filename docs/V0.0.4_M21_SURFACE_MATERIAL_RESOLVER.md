M21 establishes one deterministic surface-material resolver between M18
physical exposure/M20 biome weights and rendering.

## Authority boundary

M18 remains authoritative for the physical exposed material and exposed
bedrock identity.

M20 remains authoritative for biome weights.

M21 owns only the derived rendered material blend. It does not rewrite M08,
M18, M02 geology or biome placement.

The shared relationship is:

```text
M18 physical exposed surface
× M20 resolved biome weights
× shared slope / curvature / moisture / process masks
= M21 rendered material blend
```

## Material vocabulary

Physical base kinds:

- bedrock;
- regolith;
- soil;
- sand;
- debris.

Explicit physically plausible overlays:

- snow;
- moss;
- litter;
- dust.

Only a physical bedrock contribution carries a `RockTypeId`. Loose material
and overlays never masquerade as geology.

## Biome surface layer stack

`BiomeDefinition::surface.layers` is an ordered stack of
`BiomeSurfaceLayerRule` values.

Each layer declares:

- overlay kind;
- strength;
- compatible M18 exposed-material mask;
- slope range/falloff;
- curvature range/falloff;
- moisture range/falloff;
- enabled state.

The stack is semantic project state. `Biome Surface Layer` child objects are
registered through WorldSchemas and reconstructed by `SurfaceComposition` in
stable child order.

## Shared feature masks

`SurfaceMaterialFeatureMasks` supplies:

- slope;
- curvature;
- snow coverage;
- moss potential;
- litter availability;
- dust availability.

The resolver evaluates these shared fields once. Render shaders are not allowed
to independently derive a second material classification.

## Compositing

The actual M18 exposed material begins at weight 1.

Every compatible biome overlay computes an opacity from:

```text
biome weight
× biome material influence
× layer strength
× slope mask
× curvature mask
× M08 moisture mask
× process mask
```

The overlay then alpha-composites over the current normalized physical/material
blend.

This means exposed bedrock remains visible unless an explicit physical overlay
such as full snow coverage legitimately covers it.

## Renderer boundary

`terrain_render::MakeSurfaceMaterialRenderInput()` accepts only a validated
`ResolvedSurfaceMaterialBlend`.

It packs the nine canonical material weights plus exposed-bedrock identity. It
does not re-evaluate biome, slope, moisture or geology rules.

The old terrain pixel shader contained an independent slope-based
`rockBlend`. M21 removes that reclassification. Slope still affects lighting,
but it no longer decides whether rock is visually exposed.

The legacy analytic preview stream still carries its historical eight biome
color weights because that sampling path does not yet own M08/M18 material
state. M21 does not invent a second material authority to replace them. The
canonical M21 blend is the required path for consumers that have M18 physical
state.

## Acceptance coverage

`Orbit.SurfaceMaterialResolver` verifies:

- wet basalt + forest produces basalt + moss;
- dry basalt + desert produces dusty basalt;
- deep sand + desert remains physical sand;
- deep soil + forest produces a litter-covered forest floor;
- a full explicit snow overlay may physically cover bedrock;
- slope suppresses unsuitable moss through the shared mask;
- fixed inputs are deterministic;
- renderer packing preserves normalization and exposed basalt identity.

`Orbit.SurfaceComposition` additionally verifies persisted M21 surface-layer
children survive terrain regeneration.

`Orbit.TerrainSurfaceShader` DXC-compiles the production terrain pixel shader
after removal of the independent slope-to-rock classification.

## Frozen M21 boundary

From M21 onward:

- M18 decides what physical material is exposed;
- M20 decides biome weight;
- M21 combines those states with shared feature/process masks;
- biome material rules may add compatible overlays but never redefine geology;
- renderer code consumes a resolved material blend instead of reclassifying
  terrain independently.
