# Orbit V0.0.4 M28 — Studio surface-authoring UI

Status: **Implementation in progress**

M28 extends the existing Studio/editor-model stack. It does not add a separate terrain editor or require users to open the procedural graph for normal planet authoring.

## Contextual planet surface panel

The `Surface Authoring` panel resolves the selected terrain-bearing Celestial Body even while a descendant Terrain Surface, Biome, Selector, Mask, Surface Layer or Scatter Rule is selected.

For a rocky terrain-bearing body it exposes:

- Geology
- Terrain Processes
- Biomes
- Surface Cache / Debug

## Geology

The ordinary panel edits persisted Terrain Surface relief authority directly:

- macro amplitude and wavelength;
- detail amplitude and wavelength;
- detail octave count;
- maximum elevation.

It also surfaces the implemented geology families without inventing placeholder simulation properties:

- uplift / macro geology;
- virtual stratigraphy;
- rock material physics;
- fault/fold authored constraints;
- impacts/craters;
- authored geological features.

## Terrain Processes

Only process families that already passed V0.0.4 acceptance are shown:

- stream power;
- water / hydraulic erosion;
- wind / aeolian erosion;
- unified sediment exchange;
- thermal / gravity;
- glacial;
- river network / meanders;
- coastal.

Raw solver-constant walls are deliberately excluded from the ordinary workflow.

## Biome workflow

The Base Biome is shown as the non-removable residual fallback.

Adding a biome creates a real persisted `Biome Asset` plus three semantic automatic-selector children:

- temperature;
- moisture;
- elevation.

The ordinary panel edits each selector's minimum, maximum and smooth lower/upper falloff.

`Paint Local Override` creates a persisted `Biome Authored Mask`, normalizes the body-space direction, stores inner/outer radius, weight and opacity, and switches the biome to Automatic+Authored placement.

The panel also exposes surface-material influence and scatter-density multiplier. It can create a real Moss Surface Layer and Tree Scatter Rule; the new child is selected so the generic Properties inspector can edit all exact schema fields immediately.

## Advanced fields

The optional Advanced Fields section exposes:

- minimum resolved biome weight;
- hydraulic, thermal, aeolian, glacial, coastal and chemical process modifiers;
- exact automatic-selector ranges/falloffs;
- exact authored mask operation/value/opacity/radii.

This keeps the common workflow compact while preserving exact authored authority for advanced users.

## Persisted scatter integration

M28 closes the document/runtime handoff for M22 scatter rules:

- `kBiomeScatterRuleType` and all implemented fields are registered in `WorldSchemas`;
- `SurfaceComposition` converts persisted scatter children into `BiomeDefinition.scatter.layers`;
- stable runtime rule identity is derived from the semantic child ObjectId.

Studio scatter edits therefore feed the same deterministic M22 runtime policy.

## Surface cache / debug

The panel reports live semantic/surface/universe state and documents the M26 physical cache identity plus M27 dependency invalidation boundary. Per-field overlays and seam visualization remain M29.

## Acceptance coverage

`Orbit.SurfaceAuthoringModel` verifies the normal workflow without opening a graph:

1. select a terrain-bearing body;
2. edit base relief;
3. add a Desert biome;
4. adjust temperature, moisture and elevation preference;
5. paint a local authored override;
6. add a Moss surface layer;
7. add a Tree scatter rule;
8. edit material/scatter/process settings;
9. select a semantic child while retaining planet context.

`Orbit.SurfaceComposition` additionally verifies that persisted scatter-rule children reach the runtime `BiomeDefinition`.

The milestone remains in-progress until branch-head warnings-as-errors compilation and the isolated V0.0.4 regression lane pass.
