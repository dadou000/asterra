## Current frozen execution boundary

M01 completion means all new V0.0.4 terrain-process code must use canonical planet/body-space position and a physical-meter sample footprint at public physical-sampling boundaries. Cube/tile/clipmap coordinates remain permitted for page addressing, storage and rendering, but they are not procedural terrain coordinates.

Generated terrain remains derived state. Camera motion may change residency/request priority but may not alter physical page identity, procedural seeds, or terrain-process inputs.

## Next implementation target

**M02 — Geological Material Library**

The next implementation should add the real authored geological material records described by the V0.0.4 scaffold, with initial differential-erosion coverage for basalt, granite, sandstone, limestone and unconsolidated volcanic ash. No geology implementation should be placed under `BiomeService`; geological substrate remains independent authority.
