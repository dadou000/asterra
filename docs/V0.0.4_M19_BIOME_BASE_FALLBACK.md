M19 introduces the persistent/runtime biome-definition boundary and guarantees
that every terrain-bearing rocky body always has valid biome coverage.

## Rocky-body ownership

For V0.0.4, a rocky planet/body is a body that owns a `Terrain Surface`
capability.

`SurfaceComposition` now creates exactly one `BiomeService` for every such
body.

Bodies without a terrain surface do not receive this terrain-biome capability.

## BaseBiome invariant

Every `BiomeService` contains one implicit, stable `BaseBiome`.

The BaseBiome:

- is created with the service;
- has a deterministic ID derived from the stable body ID;
- is stored separately from optional authored biomes;
- cannot be removed through optional-biome mutation;
- is always present in resolved coverage, including with zero residual weight;
- receives all residual coverage not consumed by eligible optional biomes.

A newly created terrain-bearing planet therefore resolves to 100% BaseBiome
without requiring an authored biome asset.

## BiomeDefinition

M19 adds the canonical definition:

```cpp
struct BiomeDefinition
{
    BiomeId id;
    std::string name;
    BiomePlacementRules placement;
    BiomeSurfaceRules surface;
    BiomeScatterRules scatter;
    BiomeProcessModifiers processModifiers;
};
```

The rule records already have durable runtime semantics:

- placement: enable state and minimum resolved-weight eligibility threshold;
- surface: material influence multiplier consumed by later M21 composition;
- scatter: density multiplier consumed by later scatter work;
- process modifiers: non-negative hydraulic, thermal, aeolian, glacial,
  coastal and chemical-weathering multipliers.

These modifiers never overwrite intrinsic M02 geological properties.

## Residual coverage

`BiomeService::Resolve()` accepts optional-biome weight contributions.

Resolution is deterministic:

1. stale/unknown optional IDs are ignored;
2. disabled biomes are ignored;
3. contributions below that biome's minimum threshold are ignored;
4. accepted optional weights consume coverage;
5. remaining coverage belongs to BaseBiome;
6. if optional weights exceed one, they are normalized to one and BaseBiome
   receives zero.

The returned list always contains exactly one BaseBiome entry.

Deleting an authored biome therefore cannot leave undefined terrain, even if a
stale derived weight still references the deleted ID.

## Authored biome assets

The existing persistent `Biome Asset` schema is now runtime-backed rather than
an identity-only placeholder.

Biome assets parented under a `Terrain Surface` are composed into that body's
`BiomeService`.

Their `BiomeId` is deterministically derived from the stable semantic object
ID, so rebuilds preserve biome identity.

M19 persists:

- minimum resolved weight;
- surface material influence;
- scatter density multiplier;
- hydraulic erosion multiplier;
- thermal transport multiplier;
- aeolian transport multiplier;
- glacial erosion multiplier;
- coastal erosion multiplier;
- chemical weathering multiplier.

Adding/removing the semantic biome object causes the rebuilt service to
add/remove the optional definition while retaining the BaseBiome.

## Geology separation

`BiomeDefinition` contains no owned M02 `RockTypeId`.

A biome asset is therefore reusable across multiple geological substrates.

M19 acceptance explicitly resolves the same forest biome over exposed basalt
and exposed granite M18 states while retaining one biome definition.

M20 may use geology/material as one placement selector, but that remains a
filter/input to biome weighting, not ownership of geology by the biome.

## Legacy analytic biome weights

The earlier fixed eight-channel `terrain::BiomeWeights` produced by the
analytic terrain source remains compatibility/preview derived data.

It is not the M19 biome authority.

The new `BiomeService` + authored `BiomeDefinition` model is the V0.0.4
authority that M20-M22 build upon.

## Acceptance coverage

`Orbit.TerrainBiome` verifies:

- a BaseBiome-only rocky planet is valid;
- BaseBiome receives 100% coverage with no optional biome;
- sub-threshold optional weights fall back completely to BaseBiome;
- accepted optional weights leave residual BaseBiome coverage;
- oversubscribed optional weights normalize deterministically;
- BaseBiome cannot be removed;
- removing an optional biome returns stale coverage to BaseBiome;
- the same biome definition can occur over basalt and granite without
  duplicating the biome asset.

`Orbit.SurfaceComposition` now additionally verifies:

- every terrain-bearing body receives one BiomeService;
- the initial service contains exactly one definition;
- an authored Biome Asset is composed into the service;
- persisted placement/scatter properties reach the runtime definition;
- deleting the authored biome restores the BaseBiome-only service;
- the body ID remains stable across biome add/remove rebuilds.

## Frozen M19 boundary

From M19 onward:

- every terrain-bearing rocky body owns exactly one BiomeService;
- every BiomeService always contains exactly one BaseBiome fallback;
- optional biome deletion cannot create undefined coverage;
- biome assets own ecological placement/surface/scatter/process rules;
- biome assets do not own geological substrate identity;
- the old fixed analytic biome channels are not the new authoring authority.
