M20 extends the M19 per-rocky-body `BiomeService` with weighted automatic
placement, durable authored overrides, and explicit composition modes.

## 1. Placement authority

Biome placement has two independent authored inputs:

- procedural selector rules stored on the biome asset;
- authored mask objects stored as semantic children of the biome asset.

Generated terrain pages are not authority for either input.

The final biome weights are derived from those rules and current physical /
climate process fields.

## 2. Automatic selector catalog

`BiomeSelectorField` covers every M20 field:

- temperature;
- moisture;
- rainfall;
- elevation;
- slope;
- aspect;
- latitude;
- continentality;
- distance to coast/water;
- drainage;
- soil depth;
- sand depth;
- geology/material identity;
- solar exposure;
- wind exposure;
- snow persistence;
- arbitrary user field.

Each numeric selector contains a full-weight plateau plus independent lower and
upper smooth falloffs.

Aspect selectors support wrapped intervals across 0/2π.

Geology selectors compare the physical substrate rock identity; they do not
change M02/M08 geology.

Arbitrary user fields use deterministic stable field IDs derived from names.

## 3. Selector composition

Multiple selectors for the same physical field form a smooth OR group by taking
their maximum weight.

Different selector fields combine multiplicatively.

This allows one biome asset to accept multiple temperature bands, multiple
geological materials or multiple authored user-field bands without duplicating
that biome definition.

## 4. Placement modes

Every optional biome supports:

```text
Automatic
Authored
Automatic + Authored
```

Automatic mode uses only procedural selectors.

Authored mode starts at zero and evaluates only authored mask operations.

Automatic + Authored begins from automatic weight and then composes authored
masks in stable semantic child order.

## 5. Authored mask operations

`BiomeAuthoredWeightOperation` implements:

```text
Add
Subtract
Replace
Multiply
Min
Max
```

Masks are canonical body-space spherical brushes with:

- stable mask ID;
- center unit direction;
- inner/outer radius in physical metres;
- smooth falloff;
- global-mask option;
- authored value;
- opacity;
- enabled state.

The final value is clamped to [0,1].

## 6. Residual BaseBiome

M20 feeds evaluated optional-biome weights back through the frozen M19 resolver.

Therefore:

- BaseBiome remains exactly one residual/fallback entry;
- optional weights under their threshold fall back to BaseBiome;
- optional coverage above one is normalized;
- deleting an optional biome cannot leave undefined terrain.

## 7. Persistent semantic authoring

M20 adds permanent world-model types:

- `Biome Automatic Selector`;
- `Biome Authored Mask`.

Selector properties include field, minimum, maximum, lower/upper falloff,
material ID, user field, invert and enabled.

Mask properties include operation, body-space center, inner/outer radius,
global flag, value, opacity and enabled.

They are normal semantic scene children under a Biome Asset and therefore use
the existing V0.0.3 command/undo/database authority path.

Terrain regeneration never rewrites these objects.

## 8. SurfaceComposition integration

`SurfaceComposition` reconstructs M20 placement definitions from semantic
Biome Asset children.

Stable authored-mask identity is derived from the semantic object ID.

Procedural selector objects and authored mask objects remain independent, so
editing automatic climate rules does not rewrite paint/mask identity.

## 11. Frozen M20 boundary

From M20 onward:

- biome placement is weighted, not categorical;
- automatic rules and authored masks are separate authorities;
- authored masks survive terrain regeneration;
- biome placement may inspect physical geology/material state but cannot mutate
  geological identity;
- BaseBiome remains the residual fallback;
- material rendering must consume resolved biome weights instead of
  independently reclassifying climate.
