# Orbit V0.0.4 — M12 Thermal / Gravity Erosion

Status: **implemented and verified**

Branch: `orbit`

Verified implementation head: `db314e1d9176ab6a9c0464957dbfb4198a6740a9`

Implemented: 2026-09-18

M12 adds local gravity-driven slope failure on the M08 physical material
column. It redistributes unstable loose material by material-specific angle of
repose and treats exposed bedrock as a separate fracture/talus process rather
than a generic smoothing surface.

## 1. Physical rule

M12 distinguishes two failure families.

### Loose granular/cohesive material

The exposed M08 loose layer uses its own critical repose angle:

```text
sand       33°
regolith   37°
debris     40°
soil       46°
```

Defaults are configuration values, not hard-coded material identity.

A cell only proposes movement when its steepest lower D8 neighbor exceeds the
active material's critical slope.

### Exposed bedrock

Bedrock does not use a loose-material repose angle.

Its failure threshold is:

```text
minimum rock failure angle
+ competence-dependent angle range
```

where competence comes from M02 hardness and cohesion.

Failure mobility additionally uses:

- M02 fracture tendency;
- M02 hardness;
- M02 cohesion;
- configured fracture rate.

This prevents ordinary competent rock from being blurred by the same operator
used for sand/talus.

## 2. Local relaxation

Each iteration is a deterministic two-stage Jacobi update:

```text
frozen M08 surface
      ↓
one steepest-lower D8 proposal per source
      ↓
simultaneous source removal + receiver deposition
      ↓
next local iteration
```

For loose material, the geometric transfer target is approximately half of the
height excess above the repose slope because equal-area source removal and
receiver deposition both reduce the source/receiver height difference.

Movement is bounded by:

- exposed source-layer depth;
- configured maximum depth per iteration;
- relaxation coefficient;
- source-side protection allowance.

The CPU solver terminates early when the largest proposed source depth falls
below the configured local convergence tolerance.

No global terrain solve or camera-dependent recomputation is required.

## 3. Material-specific redistribution

Only the current exposed loose layer is allowed to move from a cell:

```text
debris
sand
soil
regolith
bedrock
```

This preserves the M08 physical stack rather than numerically diffusing total
height.

Loose material keeps its material identity while moving:

```text
sand     → sand
soil     → soil
regolith → regolith
debris   → debris
```

M14 later provides the unified cross-process sediment conversion/transport
contract.

## 4. Talus / debris production

If exposed bedrock actually exceeds its M02-dependent fracture threshold, M12
removes bedrock depth and converts its mass into debris at the receiving cell.

The conversion is mass-based:

```text
removed bedrock depth × bedrock density
=
deposited debris depth × debris density
```

Therefore a dense rock fragment does not incorrectly become an equal depth of
lower-density talus.

The M08 bedrock reference is not rebased during failure. Fractured rock remains
queryable as excavated bedrock mass, while the same mass appears in the debris
layer.

## 5. Protection / stability

M12 accepts an optional per-cell protection field in `[0,1]`.

Protection is source-side preservation:

```text
movement allowance = 1 - protection
```

A fully protected source cannot fail, but it may still receive material from an
unprotected neighboring slope.

The CPU result exposes per-cell:

- maximum local slope angle;
- active repose/failure angle;
- unstable flag;
- moved-out mass;
- received mass;
- bedrock-derived debris mass.

This is the M12 stability/debug field used by later process/editor tooling.

## 6. Mass conservation

For loose-only redistribution:

```text
initial loose mass = final loose mass
```

When rock fractures:

```text
initial loose mass
+ newly fractured bedrock mass
= final loose mass
```

M12 reports the independent M08 physical-column balance error.

The acceptance suite requires relative error below a few parts per million,
with differences limited to repeated f32 layer storage.

## 7. GPU implementation

`GpuThermalErosionPage` uses persistent fixed-capacity resources.

Each GPU iteration has two physical stages:

1. `kM12ComputeTransferShader`
   - reads the frozen M08 material page;
   - resolves the exposed material;
   - finds the steepest lower D8 neighbor;
   - evaluates material-specific repose or M02 rock failure;
   - writes one 16-byte transfer proposal.

2. `kM12ApplyTransferShader`
   - removes this cell's own outgoing proposal;
   - gathers the eight neighboring proposals targeting this cell;
   - deposits the incoming material;
   - writes only this cell's M08 bedrock/loose lanes.

This gather architecture avoids floating-point atomics and source/receiver
write races.

The transfer proposal is:

```text
target cell index     u32
transfer kind         u32
source depth          f32
deposit depth         f32
```

Bedrock-to-debris proposals already contain the density-converted deposit
depth.

## 8. GPU physical inputs

M12 directly consumes the existing physical GPU state:

```text
R32F      M08 bedrock
RGBA16F   M08 regolith / soil / sand / debris
R16_UINT  M02 geological material index
N² f32    protection
32-byte   M02 geological material table
```

No render clipmap, camera state or alternate heightfield participates in the
physical process.

## 9. CPU authority handoff

As with M11, M08 remains CPU terrain authority.

After GPU thermal iterations, `RecordMaterialReadback()` snapshots:

```text
bedrock
regolith
soil
sand
debris
moisture
```

into a 24-byte-per-cell GPU buffer and copies it to persistent host readback.

After the submission fence completes,
`ApplyMaterialReadbackToCpu()` updates the matching
`MaterialColumnPage` while retaining:

- stable RockTypeId;
- reference bedrock elevation;
- process/scratch identity.

## 10. Acceptance coverage

`Orbit.TerrainThermalErosion` verifies:

- sand, debris and cohesive soil produce different repose behavior;
- loose-material avalanching does not smooth underlying bedrock;
- weak/fractured M02 rock fails more readily than competent basalt;
- fractured bedrock produces physical debris/talus;
- bedrock-to-debris conversion conserves mass;
- full protection prevents source failure;
- the local solver converges within a bounded iteration budget;
- fixed inputs produce deterministic material state.

`Orbit.TerrainGpuThermalShaders` DXC-compiles all three M12 compute stages.
