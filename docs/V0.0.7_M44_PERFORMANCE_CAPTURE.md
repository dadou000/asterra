# Orbit V0.0.7 — M44 Cross-Capability Performance Capture

M44 records production lighting/GI and universal-volume behavior across representative GPU capability classes. It does **not** substitute synthetic timings for unavailable hardware measurements.

## Capture artifact

`orbit.v0.0.7.performance.v1` JSON captures are produced from the live M42 profiler snapshots and RHI device identity.

Every capture records:

- exact Git commit stamped at configure/build time;
- adapter name;
- graphics API;
- acceleration-structure, ray-query, RT-pipeline, mesh-shader and VRS capability flags;
- viewport resolution;
- named scenario and settings profile;
- configured lighting budgets and measured per-section GPU timings when available;
- requested/scheduled exact visibility, GI-cache, reflection and emissive work counts;
- ray-query availability and actual backend selection;
- radiance-cache resident/dirty cell count, total GPU footprint and scheduled update count when supplied by the runtime capture host;
- selected-volume field footprint/residency;
- volume solver requested/executed iterations, GPU budget and measured GPU milliseconds;
- resolved Live/Coarse/Passive/Baked volume representation;
- raymarch/shadow steps and explicit pixel-step work products.

Volume render pixel-step values are workload descriptors, not milliseconds. They remain separate from measured GPU timings so a missing renderer timestamp cannot be misreported as measured cost.

## Required hardware matrix

Record the same commit, scenario, resolution and settings on at least:

1. one Vulkan GPU without hardware ray query available to Orbit;
2. one Vulkan GPU with acceleration structures + ray query available;
3. the RT-capable GPU with Hardware Ray Query disabled through the normal Studio runtime policy, providing an A/B on identical hardware.

Recommended baseline resolution is 1920×1080. Additional 2560×1440 and 3840×2160 captures are useful but must be separate artifacts rather than mixed averages.

## Lighting capture protocol

Use the M43 **RT A/B** scenario or another fixed authored scene with non-zero visibility/GI work.

For each capture:

1. keep lighting budgets identical;
2. allow the scene to reach a stable profiler state;
3. record the RHI capability flags and selected visibility backend;
4. record requested/scheduled exact-query counts and per-section GPU timings;
5. do not raise GI, reflection or emissive budgets merely because RT is present.

`ValidateV007RtAutoPair()` passes only when the two captures retain the same configured budget and scheduled work counts while the RT-capable capture selects hardware ray query and the non-RT capture does not.

Visual-quality evidence remains part of the M43/M46 GPU tolerance gate; M44's pair validator proves the performance-policy invariant rather than assigning an image-quality score.

## Volume Auto capture protocol

Use one authored volume and capture it twice without changing its semantic settings:

- **Near:** projected importance high enough for `Live`;
- **Far:** distance/projected importance low enough for Auto to demote to `Coarse`, `Passive`, or validated `Baked`.

Record:

- representation and blend state;
- field allocation bytes/resident tiles;
- requested/executed solver iterations;
- solver GPU milliseconds when timing is valid;
- raymarch/shadow step counts;
- render/shadow pixel-step work.

`ValidateV007VolumeAutoPair()` rejects a far capture that remains Live or increases render work, live solver iterations, or resident field memory relative to the near capture.

## File naming

Recommended format:

```text
Reports/V007/M44/<scenario>/<adapter>-<settings>-<width>x<height>-<commit>.json
```

Sanitize adapter names for filesystem use, but preserve the unsanitized adapter string inside the JSON report.

## Acceptance evidence

M44 code acceptance requires:

- durable versioned JSON serialization;
- automatic adapter/API/capability/resolution/settings/commit metadata;
- lighting/GI work and timing capture;
- radiance-cache footprint/update fields;
- volume simulation timing and representation/work capture;
- deterministic RT-budget and volume-Auto pair validators;
- `Orbit.V007PerformanceCapture` regression.

Release/hardware acceptance remains open until real captures from the representative matrix are checked in or attached to the release evidence. No placeholder timing values count as hardware evidence.
