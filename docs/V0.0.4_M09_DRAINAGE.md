# Orbit V0.0.4 — M09 GPU Drainage and Depression Routing

Status: **implemented and verified**

Branch: `orbit`

Implemented: 2026-09-18

M09 derives drainage from the mutable M08 physical surface without turning
render pages, camera position, or cache residency into terrain authority.

## 1. Physical input

The drainage surface is the actual M08 top surface:

```text
bedrock height
+ regolith
+ soil
+ sand
+ debris
= physical drainage surface
```

The CPU reference path reads `MaterialColumnCell::SurfaceHeightMeters()`.
The GPU path reads the M08 `R32F` bedrock and `RGBA16F` loose-material
UAVs directly. It does not round-trip through CPU staging and does not create a
second authoritative heightfield.

## 2. Drainage products

Each physical cell derives:

- deterministic D8 downstream direction;
- conditioned drainage elevation;
- depression-fill depth;
- contributing drainage area;
- discharge;
- authored drainage guidance sample;
- explicit outlet state.

`DrainagePage::Revision()` is the M09 drainage revision field. Its stable
fingerprint combines:

- the full M08 `PhysicalTerrainPageKey`;
- depression policy;
- minimum drainage drop;
- authored-guidance weight;
- neighboring boundary revision.

Camera/view/cache revisions are intentionally absent.

## 3. Depression policies

M09 exposes two real routing policies:

### PreserveClosed

The physical surface is left unchanged for routing. A cell with no strictly
lower neighbor remains a closed sink.

### FillToBoundary

A priority flood on the CPU reference path, or the GPU depression-conditioning
pass on the GPU path, derives a monotonically draining routing surface.

The fill changes only the derived drainage elevation. It never rewrites the M08
material column.

## 4. Page-boundary contract

A page edge is **not** an implicit outlet.

`DrainagePageHalo` supplies a one-cell fixed boundary ring from neighboring
physical pages. Each boundary sample carries:

- physical surface height;
- neighboring conditioned height;
- authored drainage guidance;
- accumulated drainage area;
- accumulated discharge;
- local flow direction.

The neighboring conditioned height is a fixed boundary condition for depression
routing. Cross-page area/discharge is injected into the receiving page before
its internal accumulation pass.

A `FillToBoundary` CPU build with a missing halo is rejected rather than
silently routing water off a page edge.

Cube-face neighbor discovery/remapping stays in the M01/world neighborhood
layer; M09 consumes boundary samples in the receiving page's local orientation.

## 5. Deterministic D8 flow

Candidate downstream cells must have strictly lower conditioned elevation.
Authored M04 drainage guidance only re-ranks already-downhill candidates:

```text
score = physical_slope * (1 + guidance_weight * guidance)
```

with guidance clamped to `[-1, 1]` and weight constrained below `1`.

Therefore authored drainage intent cannot manufacture an uphill edge or become
height authority.

Ties use stable row-major identity, so the same physical inputs produce the same
flow graph.

## 6. CPU accumulation

The CPU reference page sorts cells by descending conditioned drainage elevation.
Because every directed edge is strictly downhill, upstream cells are always
processed before their recipients.

Each cell begins with:

```text
area      = physical cell area
discharge = runoff depth rate * physical cell area
```

Imported boundary flux is added before internal propagation.

## 7. GPU page layout

`GpuDrainagePage` uses one padded `(N + 2)²` graph around an `N²` M08
physical page.

Inputs:

```text
M08 R32F bedrock UAV
M08 RGBA16F loose-material UAV
(N+2)² f32 conditioned boundary ring
N² f32 runoff
N² f32 M04 drainage guidance
N² f32 incoming drainage area
N² f32 incoming discharge
```

Outputs:

```text
(N+2)² f32 conditioned drainage elevation
(N+2)² f32 drainage area
(N+2)² f32 discharge
(N+2)² u32 downstream index
```

The output ring receives flux from core cells and can be exchanged with
neighboring pages.

All intermediate graph buffers are fixed GPU pools allocated by
`GpuDrainagePage`; `Dispatch()` performs no heap/resource allocation.

## 8. Fast flow accumulation

The GPU accumulation stage follows the rake-compress stream-tree strategy from
Jain et al. FastFlow rather than propagating flow one river cell per dispatch.

Pipeline:

```text
conditioned surface
      ↓
deterministic SFD
      ↓
inverse donor matrix (max 8 donors/cell)
      ↓
rake leaves + pointer-jump single-donor chains
      ↓
repeat ceil(log2(nodeCount)) rounds
      ↓
drainage area + discharge
```

Only integer donor-slot allocation uses atomics. Floating-point area/discharge
accumulation is gather-based over the ping-pong donor graph.

The same graph reduction is used for drainage area and discharge, keeping both
products topologically consistent.

## 9. GPU depression routing

M09 reuses Orbit's existing GPU depression conditioner, but now runs it on the
padded physical page whose outer ring is neighboring conditioned state rather
than treating the M08 page edge itself as an outlet.

This is a real bounded GPU relaxation pass and is deterministic for fixed
inputs. It is not represented as the FastFlow depression-graph/MST algorithm;
that remains a performance optimization opportunity rather than a correctness
placeholder.

Sea-level cells are explicit terminal outlets in both conditioning and the
downstream graph.

## 10. Acceptance coverage

`Orbit.TerrainDrainagePage` verifies:

- M09 uses the complete M08 physical surface, including loose layers;
- `PreserveClosed` retains a true closed sink;
- `FillToBoundary` conditions the same sink into a routed surface;
- M04 guidance cannot create uphill flow;
- identical physical/revision inputs produce identical routing and revision;
- process and neighbor-boundary revision changes invalidate M09;
- drainage area and discharge remain continuous across a two-page exchange;
- missing neighbor state is rejected for `FillToBoundary`.

`Orbit.TerrainGpuDrainageShaders` compiles all M09 compute kernels through
Orbit's DXC backend without requiring a Vulkan physical device. This catches
shader syntax/binding regressions in hosted CI.

Actual Vulkan execution remains covered by Orbit's existing workstation GPU
test path.

## 11. M09 invariants

1. **M08 physical material columns remain height authority.**
2. **Drainage elevation is derived state and may be regenerated.**
3. **A page edge is not automatically an outlet.**
4. **Neighbor-conditioned state participates explicitly in routing identity.**
5. **M04 drainage guidance influences routing but cannot create uphill flow.**
6. **Flow edges are deterministic and strictly downhill.**
7. **Area and discharge are accumulated on the same directed graph.**
8. **Camera/cache residency cannot change drainage identity.**
9. **GPU dispatch uses persistent resources rather than per-dispatch allocation.**
10. **Cross-page flux is explicit data, not inferred from render clipmaps.**
