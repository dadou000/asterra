# Orbit V0.0.4 M26 — Persistent GPU terrain cache

Status: **Implementation in progress**

M26 adds persistent GPU ownership for expensive solved/derived physical terrain pages.

## Cache identity

`PersistentGpuTerrainCacheKey` contains only stable physical page address, physical process LOD and terrain authority revisions. Camera, render clipmap, viewport, frame index and GPU slot identity are absent.

## Cached data

`CachedGpuTerrainPage` owns real RHI `Buffer` and `Texture` resources. A page must declare solved/derived terrain products and non-zero GPU bytes before it is cacheable. Cheap standalone procedural noise octaves are not represented as cache products.

## Reuse

`GetOrCreate` generates on a miss and returns the resident solved page on subsequent hits. Stationary use and revisiting still-resident terrain therefore produce zero regeneration after warmup.

## Lifetime and budget

Shared ownership allows in-flight solver/renderer users to keep RHI resources alive after the cache index evicts a page. The cache enforces maximum resident bytes and maximum page count with deterministic least-recently-used eviction.

## Invalidation

Revision changes naturally create new keys. `InvalidateAddress` removes every physical LOD/revision entry for one stable page address, providing the M27 dependency-invalidation handoff.

## Telemetry

The cache tracks hits, misses, generations, insertions, evictions, resident pages and resident GPU bytes.

## Acceptance coverage

`Orbit.TerrainGpuPersistentCache` verifies actual RHI byte accounting, one generation after stationary warmup, revisit reuse, physical-LOD/revision identity, LRU behavior, external lifetime after eviction, address invalidation and stable physical-only fingerprints.

The milestone remains in-progress until branch-head warnings-as-errors compilation and the isolated terrain regression lane pass.
