M18 establishes one canonical physical exposed-surface resolver above the M08
material column and M02 geological substrate.

## Authority boundary

The exposed physical material is determined only by the actual topmost M08
material:

```text
debris
sand
soil
regolith
bedrock
```

Biome state is not an input to the resolver and cannot choose underlying rock
identity.

The M08 column remains authoritative for:

- loose-layer thickness;
- bedrock identity;
- physical surface elevation;
- moisture.

M02 remains authoritative for intrinsic bedrock properties.

## Geology sample

`SampleColumnGeology()` resolves the M02 record for the
`MaterialColumnCell::bedrockMaterial` identity already stored in M08.

`GeologySample` contains:

- stable `RockTypeId`;
- hardness;
- cohesion;
- hydraulic erodibility;
- aeolian erodibility;
- permeability;
- chemical weatherability;
- fracture tendency;
- density.

A missing M02 material is an invalid physical page rather than a biome fallback.

The canonical resolver rejects a geology sample whose `RockTypeId` disagrees
with the M08 column. This prevents a consumer from substituting a biome-selected
rock type.

## Canonical resolved state

`ResolveSurface()` returns `ExposedSurfaceState` containing:

- physical exposed material kind;
- substrate rock identity;
- exposed rock identity when bedrock is actually visible;
- thickness of the exposed loose layer;
- physical surface height;
- M08 moisture;
- standing-water depth;
- snow depth;
- intrinsic M02 geology sample.

When a loose material covers rock, `exposedRock` is invalid by design. The
underlying `substrateRock` remains available without pretending it is visible.

## Physical transitions

Because the resolver reads M08 directly:

- removing debris exposes the next real layer;
- removing sand can reveal soil;
- removing soil can reveal regolith;
- exhausting all loose cover reveals the M02 bedrock identity automatically;
- depositing sand over exposed bedrock immediately changes exposure to sand;
- deposition does not rewrite substrate geology.

No explicit “set exposed material” command exists.

## Process-derived fields

M18 forwards limited process-derived state used by shared consumers:

- standing-water depth;
- snow depth.

These fields cannot alter the resolved physical material or geological identity.

Biome data remains absent from this contract.

## Renderer consumer boundary

`terrain_render::MakePhysicalSurfaceRenderInput()` accepts only an
`ExposedSurfaceState`.

It does not accept biome weights or a raw geology override.

This is the M18 physical-input boundary for rendering. Full biome/material
surface blending remains M21 work.

## Scatter consumer boundary

A new lightweight `OrbitTerrainScatter` module provides
`MakePhysicalSurfaceScatterInput()`.

It also accepts only the canonical `ExposedSurfaceState`.

M18 intentionally adds no biome placement/scatter rules; those arrive in M19
and M20. The module only freezes the physical substrate/exposure input that
future scatter rules must consume.

## Acceptance coverage

`Orbit.TerrainSurfaceResolver` verifies:

- a basalt column initially covered by soil resolves as soil;
- removing the actual soil/regolith cover automatically exposes basalt;
- exposed basalt carries the M02 basalt identity;
- depositing sand automatically changes exposure to sand;
- sand deposition does not change the basalt substrate identity;
- renderer and scatter adapters receive the same material class;
- renderer and scatter adapters receive the same substrate/exposed-rock IDs;
- water/snow process fields do not change physical material identity;
- a geology sample that disagrees with the M08 substrate is rejected.

## Frozen M18 boundary

From M18 onward:

- physical exposure comes from M08;
- bedrock identity comes from M02/M08, never a biome;
- process fields may modify later presentation/placement decisions but cannot
  replace the physical material;
- renderer and scatter-facing systems consume the same canonical resolved
  physical state;
- M21 may add biome-compatible visual overlays, but it must build on this state
  rather than bypassing it.
