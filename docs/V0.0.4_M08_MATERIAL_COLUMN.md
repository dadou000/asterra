# Orbit V0.0.4 — M08 Physical Material-Column GPU Page

Status: **implemented; verification pending**

Branch: `orbit`

M08 establishes the mutable physical terrain column that later drainage, hydraulic, aeolian, thermal and biome systems consume. CPU material-column state is authority; the GPU page is a derived packed mirror.

## 1. Physical column

Each cell stores:

```text
debris
sand
soil
regolith
bedrock
```

plus:

- bedrock height;
- stable M02 `RockTypeId`;
- moisture;
- one temporary process scalar;
- reference bedrock height for process mass accounting.

The fixed top-down erosion order is:

```text
debris → sand → soil → regolith → bedrock
```

Loose material must be exhausted before bedrock can be cut.

## 2. Surface exposure

`MaterialColumnCell::ExposedSurface()` returns the highest nonzero physical layer.

Therefore deposition naturally covers previously exposed bedrock without rewriting geology:

```text
bedrock exposed
     ↓
deposit sand/debris/etc.
     ↓
loose material exposed
     ↓
RockTypeId remains substrate authority
```

## 3. Mass accounting

`MaterialColumnPage::QueryMass()` reports:

- regolith mass;
- soil mass;
- sand mass;
- debris mass;
- bedrock mass excavated below the page's reference bedrock surface.

Loose densities are explicit M08 page parameters.

Bedrock excavation uses the density from the M02 `GeologicalMaterialLibrary`, so substrate identity and intrinsic density remain geology-owned.

`MaterialRemoval` records the depth and mass removed from every layer for a mutation.

## 4. M07 impact coupling

M07 crater process channels feed M08 directly:

```text
M07 excavationDepth
      ↓
M08 top-down erosion

M07 ejectaThickness
      ↓
M08 debris deposition

M07 rayField
      ↓
M08 temporary process scalar
```

M07 signed display/topographic relief is not converted into an immutable height stamp. Physical excavation/ejecta channels remain available to later process solvers.

## 5. Packed GPU page

The validated M08 GPU layout is:

```text
R32F        bedrock height
RGBA16F     regolith / soil / sand / debris
RG16F       moisture / temporary scalar
R16_UINT    geological material table index
```

This is exactly:

```text
4 + 8 + 4 + 2 = 18 bytes / texel
```

across four texture lanes.

The CPU page keeps stable 128-bit M02 rock IDs. GPU pages store the corresponding compact `R16_UINT` index into the M02 geological material GPU table.

## 6. Vulkan RHI support

M08 extends Orbit's RHI with:

- `R16_Float`;
- `RG16_Float`;
- `RGBA16_Float`;
- `R16_UInt`.

The Vulkan backend maps these to:

- `VK_FORMAT_R16_SFLOAT`;
- `VK_FORMAT_R16G16_SFLOAT`;
- `VK_FORMAT_R16G16B16A16_SFLOAT`;
- `VK_FORMAT_R16_UINT`.

`CopyBufferToTexture` now derives upload byte size from the destination texture format rather than assuming RGBA8.

## 7. GPU resources

`GpuMaterialColumnResources` owns the four UAV-capable textures and persistent host-visible staging buffers.

Upload flow:

```text
MaterialColumnPage
      ↓
PackGpuPage()
      ↓
four tightly-packed CPU lanes
      ↓
persistent staging buffers
      ↓
CopyBufferToTexture
      ↓
UnorderedAccess textures
      ↓
M09+ compute processes
```

Persistent staging buffers remain alive until GPU submission rather than being temporary command-recording objects.

## 8. Float16 packing

Loose material, moisture and temporary-process lanes use deterministic IEEE-754 binary16 conversion.

The page exposes debug-only `FloatToHalfBits()` / `HalfBitsToFloat()` helpers so tests can validate the exact shader-facing payload.

## 9. Acceptance coverage

`Orbit.TerrainMaterialColumn` verifies:

- loose material mass can be queried;
- bedrock excavation mass uses M02 rock density;
- debris/sand/soil/regolith are removed before bedrock;
- deposition covers exposed rock without changing substrate identity;
- M07 excavation/ejecta/ray channels mutate the physical column;
- the packed page is exactly 18 bytes/texel;
- half-float layer payloads decode within tolerance;
- the geological material lane uses the M02 GPU table index;
- the RHI texel sizes match the M08 layout.

The isolated terrain CI also compiles `OrbitTerrainGpu`, ensuring the real Vulkan-facing M08 resource uploader is warnings-as-errors clean.

## 10. M08 invariants

1. **CPU material-column state is authority; GPU pages are derived mirrors.**
2. **Loose material erodes before bedrock.**
3. **Bedrock physics comes from M02 geological identity.**
4. **Deposition covers substrate; it does not redefine substrate.**
5. **Material mass is queryable.**
6. **M07 excavation/ejecta feed physical layers rather than protected height stamps.**
7. **GPU packing is explicit and fixed at 18 bytes/texel across four texture lanes.**
8. **Temporary process channels are scratch state, never project authority.**

## 11. Next boundary

M09 — GPU Drainage and Depression Routing can consume M08 bedrock + loose-layer surface height to compute deterministic flow direction, depression handling, drainage area/discharge and cross-page routing.
