# Orbit V0.0.4 — M00 Frozen Surface Contracts

Status: **implemented**

This document is the implementation record for `M00 — Freeze V0.0.4 contracts` in `V0.0.4_SPEC.md`.

The contracts below are permanent public boundaries for the rocky-world surface stack. Later milestones may add data and behavior behind them, but must not bypass or reinterpret their authority rules.

## 1. Surface authority chain

```text
AUTHORITATIVE PROJECT STATE (CPU / document)

CommandService
      │
      ▼
ObjectStore / WorldDatabase
      │
      ├──────────────┬──────────────────┐
      ▼              ▼                  ▼
 Geology assets   Process assets     Biome assets
      │              │                  │
      └──────────────┴─────────┬────────┘
                               ▼
                    ProceduralGraph sources
                    + revision domains
                               │
                               ▼
                    PHYSICAL TERRAIN STATE
                   geology / water / material
                               │
                               ▼
                     immutable surface views
                               │
                     ┌─────────┴─────────┐
                     ▼                   ▼
                Biome policy        render/material
                     │                   │
                     └─────────┬─────────┘
                               ▼
                    DERIVED GPU PAGE CACHE
                               │
                               ▼
                           Rendering
```

Authority rules:

- Project authoring is persisted through `CommandService -> ObjectStore -> WorldDatabase`.
- `scene::MutationKey` can only be constructed by `commands::CommandService`; terrain, biome, editor, plugin and RPC code cannot write around the command path.
- Physical terrain generation owns generated bedrock/material evolution, but generated products are derived state and never replace project authority.
- `WaterPhysical` is a separate physical authority domain and participates in terrain invalidation through its own revision.
- `BiomePolicy` may inspect immutable physical surface fields and resolve coefficients/dressing. It does not receive mutable bedrock/material buffers.
- Cache and view-interest state are derived only.

## 2. Stable authored surface asset type IDs

The following `schema::TypeId` values are frozen in `orbit::world_model`:

| Asset type | Symbol | High | Low |
| --- | --- | --- | --- |
| Geology | `kGeologyAssetType` | `0x4f5242495447454f` | `0x4c4f475941535431` |
| Terrain Process | `kTerrainProcessAssetType` | `0x4f52424954505243` | `0x4553534153543031` |
| Biome | `kBiomeAssetType` | `0x4f5242495442494f` | `0x4d45415353455431` |

These are persistence/schema identities, not transient runtime handles. Do not renumber or recycle them.

The asset schemas are registered now without speculative properties. Later milestones add properties only when the corresponding runtime semantics exist.

## 3. Physical page identity

The stable physical address is:

```cpp
struct PhysicalTerrainPageAddress
{
    world::PlanetId planet;
    world::PlanetTileId tile;
};
```

The generated/cache identity is:

```cpp
struct PhysicalTerrainPageKey
{
    PhysicalTerrainPageAddress address;
    u32 resolution;
    TerrainGenerationRevisions revisions;
};
```

Physical identity deliberately excludes:

- camera position;
- camera altitude;
- frame number;
- clipmap ring index;
- render LOD selection;
- GPU atlas slot;
- cache residency;
- viewport/editor state.

A view can reveal that a physical page is missing. It cannot change the identity of a physical page.

## 4. Revision domains

`TerrainGenerationRevisions` contains only canonical inputs that can change generated physical results:

```cpp
struct TerrainGenerationRevisions
{
    u64 geology;
    u64 climate;
    u64 authoring;
    u64 biome;
    u64 water;
    u64 processes;
};
```

`TerrainRevisionDomain` maps these one-to-one for V0.0.3 `ProceduralGraph` source nodes through `RevisionForDomain()`.

There is intentionally no camera/view/render revision domain.

Allowed physical generation triggers are frozen as:

```cpp
enum class TerrainGenerationTrigger : u8
{
    MissingPhysicalPage,
    AuthorityRevisionChanged,
    ExplicitBake
};
```

Camera motion alone is not a generation trigger. Moving into a region may cause a cache lookup to discover a genuinely missing physical page; the miss, not the camera transform, is the generation reason.

## 5. Deterministic seed contract

Every terrain subsystem derives deterministic seeds from:

```text
planet root generation seed
+ persisted seed domain
+ stable physical page address
+ optional stable authored object ID
```

The seed intentionally excludes page revision and page resolution.

Consequences:

- editing a parameter invalidates/rebuilds affected products without randomly relocating all procedural features;
- changing render resolution or clipmap state does not re-seed terrain;
- different physical process domains receive distinct deterministic streams;
- authored objects can receive stable object-specific streams.

`TerrainSeedDomain` numeric values are persisted domain separators. Existing values must never be renumbered.

## 6. CPU/GPU ownership and residency

| Data | Authority | Normal runtime residency | Rule |
| --- | --- | --- | --- |
| Project/world document | document | CPU + disk | Never GPU-only |
| Geology asset definitions | document | CPU | Edited only through command path |
| Terrain-process definitions | document | CPU | Edited only through command path |
| Biome definitions | document | CPU | Edited only through command path |
| Field descriptors / dependency graph | CPU | CPU | Scheduling/metadata authority stays CPU |
| Physical bedrock/material pages | derived physical product | GPU, optional CPU diagnostic/readback | Regenerate only on miss/invalidation/bake |
| Drainage/erosion/sediment working fields | derived physical product | GPU | Persistent page working state where required |
| Biome weights / surface masks | derived | GPU | Reconstructible from authority + physical state |
| Terrain mesh | derived | GPU | Never project authority |
| GPU cache atlas/slots | derived | GPU | Residency does not affect physical identity |
| Debug/readback copy | derived | CPU | Explicit asynchronous readback |

`TerrainResidency` is intentionally separate from authority and identity.

## 7. V0.0.3 integration points

### Schema + document

V0.0.4 authored surface assets use the existing `schema::SchemaRegistry`, `scene::ObjectStore` and `documents::WorldDatabase` model. Stable asset type IDs are registered by `world_model::RegisterSchemas()`.

### Commands

All persistent authored mutations use the existing `commands::CommandService`. `ObjectStore` mutation APIs require the private `scene::MutationKey` capability token, preventing terrain/editor/plugin/RPC systems from bypassing validation, transactions, undo/redo and persistence.

### Fields

V0.0.4 surface/geology/process outputs are exposed through the existing `fields::FieldRegistry` when a milestone introduces a public field. Body-owned surface fields use `FieldDomain::Surface`; residency is declared with `FieldResidency`; LOD behavior is declared with `FieldResolutionPolicy`.

Physical buffers exposed to biome/policy systems use immutable `TerrainScalarFieldView` / `TerrainSurfaceView` interfaces.

### Procedural graph

The existing `procedural_graph::ProceduralGraph` remains the sparse CPU scheduler and revision authority. V0.0.4 feeds its source nodes using the explicit `TerrainRevisionDomain` channels. GPU process nodes issue GPU work through their GPU service; the graph itself is not moved to the GPU and view state is not an invalidation source.

### Terrain cache

`TerrainPageDesc` now contains stable planet identity plus `TerrainGenerationRevisions`. Hashing uses `PhysicalPageFingerprint()` rather than the previous single opaque `sourceRevision` value.

Existing `TerrainSource` implementations remain compatible through `GenerationRevisions()`: a legacy coarse `Revision()` is mapped to the `processes` domain until that source can expose finer authority revisions.

## 8. Acceptance evidence

M00 acceptance is covered by executable contracts:

- `Orbit.TerrainContracts`
  - deterministic physical page fingerprint;
  - water/authoring revisions invalidate generated page identity;
  - view/camera values do not participate in identity;
  - deterministic domain-separated seeds;
  - immutable biome-facing physical fields;
  - explicit procedural revision-domain mapping;
  - authority-domain ownership checks.

- `Orbit.SurfaceAuthorityContracts`
  - persistent mutation capability cannot be default-constructed outside the command layer;
  - geology/process/biome type IDs are distinct;
  - all three stable authored asset schemas are registered.

## 9. M00 completion boundary

M00 freezes contracts; it does not implement the geology, erosion, biome or water solvers themselves.

The next mandatory milestone is **M01 — Surface coordinate and sampling contract**. M01 must build on these identities/revisions rather than introduce per-view or per-clipmap physical coordinates.
