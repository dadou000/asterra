# Orbit V0.0.4 M29 — Debug field visualizer

Status: **Implementation in progress**

M29 begins with a stable field/provenance contract so renderer code cannot redefine the meaning of debug modes.

## Required field catalog

`TerrainDebugField` contains exactly the 21 V0.0.4 required views:

1. Uplift
2. Bedrock Type
3. Strata
4. Regolith
5. Soil
6. Sand
7. Debris
8. Moisture
9. Exposed Material
10. Drainage
11. Water Flux
12. Sediment Flux
13. Wind
14. Aeolian Flux
15. Erosion / Deposition
16. Biome Weights
17. Final Biome
18. Scatter Density
19. Cache Residency
20. Cache Invalidation
21. Physical LOD

Each descriptor has a stable value class and an explicit upstream stage trace.

## Provenance

Visible fields trace through typed stages such as authored authority, geology, stratigraphy, material column, drainage, hydraulic state, M14 sediment, wind, aeolian state, M18 exposed surface, biome placement/resolution, deterministic scatter, M26 cache, M27 invalidation and M23 physical scale.

The visualizer therefore has a machine-readable explanation of where a displayed result came from instead of only a shader-mode number.

## Page and seam provenance

`TerrainDebugPageStamp` records:

- stable physical page address;
- physical LOD;
- generation revisions;
- cache residency;
- invalidation revision.

`ProbeSeam` uses the canonical cube-face neighbor mapping. It explicitly reports missing neighbors, physical-LOD mismatch and revision mismatch before a renderer compares actual edge values.

This makes cube-face/page seam debugging a first-class part of M29 rather than a special-case overlay.

## Typed page-field raster composition

`TerrainDebugRasterView` is a non-owning binding from one physical page field into the M29 value-class contract. Scalar, signed scalar, vector, category, boolean, revision and physical-LOD sources are all supported without creating a second terrain authority.

`ComposeTerrainDebugRgba8` converts those typed sources into tightly packed RGBA8 data. `TerrainDebugTexture` owns persistent host-visible staging plus a derived RGBA8 RHI texture and records the real `CopyBufferToTexture` transition/upload path; repeated uploads reuse the allocation. Automatic scalar ranges are derived only from finite page data, signed fields use a zero-centered diverging range, vector fields preserve direction plus magnitude, category/revision/LOD colors are deterministic hashes, and non-finite physical/process state is rendered magenta instead of being hidden.

`Orbit.TerrainDebugRaster` exercises every one of the 21 required fields through its declared value class, verifies deterministic category colors, signed zero-centered composition, visible non-finite diagnostics and strict texel-count validation.

## Live physical-page bindings

`TerrainDebugPageData` now owns stable derived debug samples for one stamped physical page and binds real V0.0.4 products without mutating them. The M08 adapter exposes bedrock identity, regolith, soil, sand, debris, moisture and actual exposed-layer identity. The M09 adapter converts canonical D8 routing plus discharge into a drainage vector. The M11 adapter exposes net directional water flux and signed cumulative deposition-minus-erosion depth. Cache residency, invalidation revision and physical LOD are generated directly from the page stamp.

Canonical producer adapters now bind M05 macro-geology uplift, M03 stratigraphic identity, M13 wind plus current aeolian mobile-mass direction, M19-M20 dominant biome weight/identity, and M22 per-cell scatter density directly from their producer records. Fields that still require scheduler-specific directional state, notably unified M14 sediment flux, remain strict typed bindings instead of synthesized values. A missing field remains explicitly unavailable and cannot silently fall back to fabricated data.

`Orbit.TerrainDebugPageData` verifies M08 value preservation, typed external binding, page-provenance fields, value-class rejection and explicit missing-field behavior.

## Value-level seam diagnostics

`CompareSeamValues` extends the page-stamp probe into real field continuity checks. It uses `NeighborAcrossTileEdge` and `RemapTileEdgeSampleIndex` to compare the source edge against the correct receiving edge, including cube-face rotations and reversed sample order. Scalar/vector fields report a maximum numerical difference with configurable tolerance; vectors are first transformed through M25's canonical boundary tangent remap into the receiving page frame. Categorical, boolean, revision and LOD fields use exact identity.

This keeps seam visualization grounded in physical page correspondence instead of comparing screen-space pixels or assuming same-face orientation. `Orbit.TerrainDebugSeam` covers a cube-face crossing plus a deliberately corrupted edge sample.

## Live physical-page selection

Studio Debug viewports now own transient physical-page selection state separate from project/session authority. A debug view derives the stable `PlanetId` directly from the composed `BodyId` bits, matching `SurfaceRegistry`, ray-casts the viewport image against the body's reference sphere, and resolves the hit through `TileForDirection`.

Entering Debug mode selects the viewport-center page once when no page is selected. Clicking the rendered viewport image selects the physical page under that cursor position. The physical tile level is an explicit debug control in [0,30]; changing it clears the previous address so the next refresh resolves a page at that physical granularity. Camera, clipmap ring, frame, GPU slot and render LOD remain excluded from the resulting `PhysicalTerrainPageAddress`.

`Orbit.StudioViewportCamera` covers stable planet identity, sphere intersection, page-address generation and invalid viewport coordinates.

## Live physical-product binding

`TerrainDebugLivePages` is the session-scoped read-only bridge between actual V0.0.4 physical-page producers and Studio. Producers assemble an immutable `TerrainDebugPageData` with `CaptureLiveTerrainDebugPage()`, passing only the real products they currently own (M03/M05/M08/M09/M11/M13/M19-M20/M22). Missing products stay unbound.

The registry is keyed only by `PhysicalTerrainPageAddress`. Republishing an address replaces its current immutable diagnostic snapshot; it does not mutate terrain authority, trigger generation or alter cache residency. `StudioSession` clears the registry whenever the composed universe generation changes, preventing snapshots from a replaced BodyRegistry/world composition from leaking into a new runtime generation.

During `StudioRenderViewSet::Refresh()`, each Debug viewport resolves its selected physical address against this registry. The panel reports whether a live snapshot exists, its physical LOD/dimensions, and whether the selected debug field is actually present. No debug value is regenerated or fabricated in Studio.

`Orbit.TerrainDebugLivePages` verifies actual-product capture, explicit missing fields, stable-address lookup and replacement semantics.

## Remaining M29 work

`StudioRenderViewSet` now owns a transient per-view M29 field selection and the Debug viewport exposes the complete 21-field catalog plus the selected field's upstream provenance without persisting presentation state into StudioSession. Next feed the resolved live `TerrainDebugPageData` through `TerrainDebugTexture` and present it in the Debug viewport. Scheduler-owned M14 directional sediment flux and explicit seam overlays remain after that.

M29 remains in-progress until all required fields are renderable from live terrain state and the trace/seam acceptance tests pass through the Studio/debug path.
