# Orbit V0.0.4 M29 — Debug field visualizer

Status: **Implementation in progress**

M29 begins with a stable field/provenance contract so renderer code cannot redefine the meaning of debug modes.

## Required field catalog

`TerrainDebugField` contains exactly the 21 V0.0.4 required views:

1. Uplift
2. Bedrock Type
3. Strata
4. Regolith
5. Soil
6. Sand
7. Debris
8. Moisture
9. Exposed Material
10. Drainage
11. Water Flux
12. Sediment Flux
13. Wind
14. Aeolian Flux
15. Erosion / Deposition
16. Biome Weights
17. Final Biome
18. Scatter Density
19. Cache Residency
20. Cache Invalidation
21. Physical LOD

Each descriptor has a stable value class and an explicit upstream stage trace.

## Provenance

Visible fields trace through typed stages such as authored authority, geology, stratigraphy, material column, drainage, hydraulic state, M14 sediment, wind, aeolian state, M18 exposed surface, biome placement/resolution, deterministic scatter, M26 cache, M27 invalidation and M23 physical scale.

The visualizer therefore has a machine-readable explanation of where a displayed result came from instead of only a shader-mode number.

## Page and seam provenance

`TerrainDebugPageStamp` records:

- stable physical page address;
- physical LOD;
- generation revisions;
- cache residency;
- invalidation revision.

`ProbeSeam` uses the canonical cube-face neighbor mapping. It explicitly reports missing neighbors, physical-LOD mismatch and revision mismatch before a renderer compares actual edge values.

This makes cube-face/page seam debugging a first-class part of M29 rather than a special-case overlay.

## Typed page-field raster composition

`TerrainDebugRasterView` is a non-owning binding from one physical page field into the M29 value-class contract. Scalar, signed scalar, vector, category, boolean, revision and physical-LOD sources are all supported without creating a second terrain authority.

`ComposeTerrainDebugRgba8` converts those typed sources into tightly packed RGBA8 data. `TerrainDebugTexture` owns persistent host-visible staging plus a derived RGBA8 RHI texture and records the real `CopyBufferToTexture` transition/upload path; repeated uploads reuse the allocation. Automatic scalar ranges are derived only from finite page data, signed fields use a zero-centered diverging range, vector fields preserve direction plus magnitude, category/revision/LOD colors are deterministic hashes, and non-finite physical/process state is rendered magenta instead of being hidden.

`Orbit.TerrainDebugRaster` exercises every one of the 21 required fields through its declared value class, verifies deterministic category colors, signed zero-centered composition, visible non-finite diagnostics and strict texel-count validation.

## Live physical-page bindings

`TerrainDebugPageData` now owns stable derived debug samples for one stamped physical page and binds real V0.0.4 products without mutating them. The M08 adapter exposes bedrock identity, regolith, soil, sand, debris, moisture and actual exposed-layer identity. The M09 adapter converts canonical D8 routing plus discharge into a drainage vector. The M11 adapter exposes net directional water flux and signed cumulative deposition-minus-erosion depth. Cache residency, invalidation revision and physical LOD are generated directly from the page stamp.

Fields whose producers live elsewhere use strict typed setters rather than synthesized values. This lets geology, stratigraphy, climate/wind, M14 boundary flux, biome resolution and scatter systems publish their real page fields when available. A missing field remains explicitly unavailable and cannot silently fall back to fabricated data.

`Orbit.TerrainDebugPageData` verifies M08 value preservation, typed external binding, page-provenance fields, value-class rejection and explicit missing-field behavior.

## Remaining M29 work

`StudioRenderViewSet` now owns a transient per-view M29 field selection and the Debug viewport exposes the complete 21-field catalog plus the selected field's upstream provenance without persisting presentation state into StudioSession. Next connect remaining canonical producers (geology/strata, M14 flux, wind/aeolian, biome resolution and scatter density) to the typed page binding, feed the selected live page into `TerrainDebugTexture`, and render it with the seam overlay.

M29 remains in-progress until all required fields are renderable from live terrain state and the trace/seam acceptance tests pass through the Studio/debug path.
