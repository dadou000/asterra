# Orbit V0.0.4 — Planet Surface Authority Scaffold

Status: **complete — V0.0.4 terrain and WaterService acceptance closed on 2026-09-20**

Branch target: `orbit`

This document defines the V0.0.4 scaffold for Orbit. It inherits the V0.0.3 production rules:

- no placeholder classes;
- no temporary editor APIs;
- no throwaway serializers;
- no fake systems that are scheduled to be replaced;
- every introduced type has a real owner, persistence rules, runtime semantics, tests, and a stable public boundary;
- authority and residency are always explicit;
- generated terrain is derived state, not project authority;
- authored intent must survive regeneration;
- GPU caches are persistent working sets of already-generated terrain and are not recomputed every frame.

V0.0.4 establishes the permanent rocky-world surface authority chain:

```text
Geology
  ↓
Physical Material Column
  ↓
Terrain Processes
  ↓
Exposed Surface State
  ↓
Biome Dressing
  ↓
Material + Scatter Resolution
  ↓
GPU Terrain Cache
  ↓
Rendering
```

The central rule is:

> **Geology defines the substrate. Terrain processes reveal and move it. Biomes interpret and dress the exposed surface.**

The second central rule is:

> **Procedural generation and authoring use the same fields and constraints. Authored intent is not a post-process stamp and is not destroyed by regeneration.**

---

## 1. V0.0.4 goals

V0.0.4 establishes these permanent engine pillars for rocky-world surfaces:

1. A strict surface authority chain: geology → terrain processes → exposed surface → biome dressing.
2. A planet-created `GeologyService`, `TerrainProcessService`, and `BiomeService`.
3. A physical terrain-column representation supporting bedrock, regolith, soil, sand, debris, moisture, and exposed material.
4. Procedural and authored geology using the same constraint system.
5. GPU-driven drainage, erosion, sediment transport, and terrain-process execution.
6. Persistent GPU terrain pages that are reused across frames and regenerated only on invalidation/cache miss.
7. A planet-wide base biome fallback plus weighted automatic/authored biome layers.
8. Surface material and scatter resolution driven by actual exposed terrain state.
9. Source-backed implementations for stream power, hydraulic erosion, wind erosion, thermal erosion, glacial erosion, crater generation, meandering rivers, vegetation/scatter, and multi-scale terrain refinement.
10. A debug/inspection UI where every contributing field can be visualized independently.

V0.0.4 does **not** make biomes responsible for geology. It does **not** store generated meshes as authority. It does **not** rerun erosion every frame.

## 2. Permanent authority rules

### 2.1 Geology is authoritative over substrate

Geology owns:

- base relief;
- tectonic/uplift intent;
- faults/folds;
- rock type;
- rock hardness;
- stratification;
- volcanic structures;
- impact/crater structures;
- geological age where relevant;
- authored canyon/ridge/basin constraints.

A biome may inspect geology but never replace it.

### 2.2 Terrain processes modify the physical surface

Terrain processes own derived physical evolution:

- water erosion;
- wind erosion;
- thermal/gravity erosion;
- sediment transport;
- deposition;
- glacial erosion;
- river incision;
- coastal redistribution where implemented;
- weathering/regolith production.

Terrain processes may expose or bury geological layers.

### 2.3 Biomes own ecological/surface dressing

Biomes own:

- surface material choices;
- vegetation;
- ground cover;
- organic litter;
- snow/ice cover rules;
- decals;
- scatter sets;
- ecosystem parameters;
- small surface dressing.

A biome may reduce erosion through vegetation/root protection or change moisture retention, but does not own large landform shape.

### 2.4 Exposed surface state is the boundary

The renderer and biome system consume the output of geology + terrain processes:

```cpp
struct ExposedSurfaceState
{
    MaterialId exposedMaterial;
    RockTypeId exposedRock;
    float soilDepthMeters;
    float sedimentDepthMeters;
    float sandDepthMeters;
    float debrisDepthMeters;
    float moisture;
    float slope;
    float curvature;
    float drainage;
    float windExposure;
};
```

## 3. Planet-created services

A rocky surface-capable planet automatically creates:

```text
Planet
├─ GeologyService
├─ TerrainProcessService
├─ BiomeService
└─ SurfaceCacheService
```

Creation is capability-driven, not hard-coded to one body class.

### 3.1 GeologyService

Owns authoritative geology descriptors and authored geological constraints.

### 3.2 TerrainProcessService

Owns registered terrain-process operators and schedules them through the procedural dependency graph.

### 3.3 BiomeService

Owns:

- `BaseBiome`;
- additional weighted biome definitions;
- automatic placement rules;
- authored biome masks/volumes/splines;
- biome material/scatter sets.

### 3.4 SurfaceCacheService

Owns resident GPU pages containing already-generated terrain and physical state.

Camera movement does not imply regeneration.

## 4. Core terrain data model

### 4.1 Material column

Do not model terrain as only a height value.

Use a compact layered physical column:

```cpp
struct TerrainMaterialColumn
{
    float bedrockHeight;
    float regolithDepth;
    float soilDepth;
    float sandDepth;
    float debrisDepth;

    RockTypeId bedrockType;

    float moisture;
    float porosity;
};
```

Surface height is:

```text
bedrockHeight
+ regolithDepth
+ soilDepth
+ sandDepth
+ debrisDepth
```

The initial implementation may pack low-dynamic-range fields into 16-bit formats where validated.

### 4.2 Virtual stratigraphy

Do not store hundreds of physical rock layers per texel.

Store geological layer functions/descriptors and evaluate only the layer intersecting the current surface. This preserves differential erosion without voxelizing the whole planet.

Reference implementation concept:

- Astrolith “Rock Layers for Real-Time Erosion Simulation”
- SideFX HeightField strata/erodability model

### 4.3 Process parameters

Every terrain process reads resolved physical coefficients:

```cpp
struct SurfaceProcessParameters
{
    float hydraulicErodibility;
    float aeolianErodibility;
    float cohesion;
    float hardness;
    float permeability;
    float sedimentCapacityScale;
    float angleOfRepose;
    float vegetationProtection;
    float moistureRetention;
};
```

Those values are resolved from:

```text
geology
+ climate forcing
+ biome modifiers
+ authored overrides
```

## 5. CPU/GPU residency rules

| Data | Authority | Runtime residency |
| --- | --- | --- |
| Geology definitions | SQLite/CPU | CPU |
| Rock/material library | asset DB/CPU | CPU + compact GPU table |
| Authored geology constraints | SQLite/CPU | CPU descriptors + GPU field pages when active |
| Biome definitions | SQLite/CPU | CPU + compact GPU rules |
| Procedural graph | CPU | CPU |
| Dense height/material pages | derived | GPU |
| Drainage/flow fields | derived | GPU |
| Erosion state | derived | GPU |
| Sediment/moisture fields | derived | GPU |
| Final surface masks | derived | GPU |
| Scatter instances | derived | GPU, streamed |
| Terrain mesh | derived | GPU |
| Project authority | disk/CPU | never GPU-only |

GPU readback is explicit and asynchronous.

GPU terrain pages are persistent across frames and regenerate only if missing or invalid.

## M26 — Persistent GPU terrain cache

This milestone enforces the cache behavior discussed for Orbit.

Flow:

```text
physical page requested
       ↓
cache lookup
       ↓
hit ───────────────→ use page
       ↓ miss
generate/solve
       ↓
store page
       ↓
reuse across frames
```

Cache key must include:

```cpp
struct SurfacePageKey
{
    BodyId body;
    SurfacePageCoord coord;
    uint8_t physicalLod;

    uint32_t geologyRevision;
    uint32_t processRevision;
    uint32_t climateRevision;
    uint32_t biomeRevision;

};
```

Rules:

- no terrain recomputation each frame;
- cache does not store cheap standalone noise octaves;
- cache stores expensive solved/derived page state;

Acceptance:

- stationary camera produces zero page generations after warmup;
- moving back to resident terrain causes zero regeneration;
- revision changes invalidate only dependent pages.

## M27 — Dependency-driven invalidation

Wire all V0.0.4 outputs into the V0.0.3 procedural dependency graph.

Examples:

```text
rock hardness change
  -> affected geology pages
  -> erosion descendants
  -> surface
  -> biome material/scatter

biome tree density change
  -> scatter only

biome moss material change
  -> surface material only

canyon spline edit
  -> local geology constraints
  -> downstream drainage/process dependency
  -> affected surface/cache
```

Acceptance:

- changing forest tree density does not rerun erosion;
- changing bedrock erodibility does rerun dependent terrain processes;
- downstream invalidation is spatially bounded where possible.

## M31 — Integration gate and V0.0.4 completion

V0.0.4 is complete only when:

- a new rocky planet automatically owns geology/process/biome/cache services;

- drainage and erosion react to that canyon;
- erosion can strip soil/sediment and expose bedrock;
- deposition can bury exposed bedrock again;

- vegetation/scatter follows biome and surface constraints;

# 8. Recommended process presets

Presets are authored data, not alternate code paths.

## Earth-like

```text
tectonic uplift     enabled
stream power        enabled
hydraulic           enabled
aeolian             enabled
thermal             enabled
glacial             climate-dependent
craters             very low / degraded
sediment            full
biomes              enabled
```

## Moon-like

```text
uplift              low/none
hydraulic           disabled
aeolian             disabled
thermal             limited
glacial             disabled
craters             dominant
regolith            dominant
biomes              disabled or BaseBiome only
```

## Dry Mars-like

```text
ancient hydraulic   generation-time optional
aeolian             strong
thermal             enabled
craters             strong
sediment            sand/regolith dominant
biomes              none unless fictional
```
