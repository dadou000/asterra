# Orbit V0.0.4 — M07 Impact / Crater Process

Status: **implemented and verified**

Branch: `orbit`

Completed: 2026-09-18

M07 adds geological impact processes downstream of the M01–M06 surface contracts. Craters are process state, not biome decoration and not protected height stamps.

## 1. Authority boundary

```text
project authority
  ImpactFieldDefinition
    ├─ deterministic procedural SFD recipe
    └─ persisted authored impact records
              ↓
M07 ImpactField
              ↓
derived crater process channels
  ├─ signed height delta
  ├─ excavation depth
  ├─ ejecta thickness
  ├─ debris field
  └─ ray field
              ↓
M08 material column
              ↓
later erosion / deposition / weathering
```

Generated crater terrain is disposable derived state. Explicit crater placements persist through `.orbitimpacts` project-authority records.

## 2. Deterministic size-frequency distribution

Procedural impacts use a cumulative power law:

```text
N(>R) ~ R^-b
```

The authored `CraterSizeFrequencyDistribution` defines:

- impact count;
- minimum radius;
- maximum radius;
- cumulative exponent.

Radius sampling is deterministic for a planet generation seed and impact ordinal.

Surface placement uses deterministic equal-area sphere sampling. It never uses cube-face UVs, clipmap rings, viewport state or cache slots.

Stable procedural `ImpactId` values are derived from the same generation seed + ordinal so regeneration reproduces impact identity as well as placement.

## 3. Simple and complex crater profiles

Each impact can request:

```text
Auto
Simple
Complex
```

`Auto` uses the field's complex-transition radius.

Simple craters contain:

- bowl excavation;
- raised rim;
- ejecta blanket.

Complex craters add:

- shallower broad excavation;
- central uplift/peak;
- wall/terrace relief;
- raised rim;
- ejecta blanket.

All profile dimensions are ratios of crater radius, keeping the process scale-independent.

## 4. Rim, ejecta, rays and debris

The rim is a smooth annular uplift centered on one crater radius.

Outside the rim, ejecta decays approximately with inverse-cube radial distance and fades smoothly at the authored ejecta extent.

Optional ray fields are deterministic angular modulation of the ejecta blanket:

```text
ray strength
ray count
stable phase from ImpactId
```

M07 also exposes a bounded debris field derived from rim/ejecta material. M08 can convert these process channels into actual debris/regolith mass.

## 5. Overlap and age ordering

`ImpactRecord::ageOrder` preserves geological sequencing for later process systems.

M07 currently composes resolved crater topography as signed process deltas. Therefore a later overlapping impact modifies already cratered derived terrain rather than replacing a prior crater asset.

The age field is retained now so later ejecta burial, material-column excavation and degradation can execute in explicit geological order without changing persisted impact identity.

## 6. Degradation

Every impact owns:

```cpp
double degradation; // 0 pristine, 1 fully degraded
```

Degradation reduces preserved excavation, rim, ejecta and ray relief.

This is intentionally not implemented as a terrain-protection mask. Crater results remain ordinary geological process output, so later hydraulic, aeolian, thermal and depositional systems can erode rims and fill bowls.

## 7. Physical footprint filtering

Tiny craters are not allowed to alias into coarse terrain pages.

M07 uses the same physical principle as M06:

```text
feature diameter <= 2 × footprint → removed
feature diameter >= 4 × footprint → full
between                           → smooth transition
```

Changing rendering LOD therefore changes representable amplitude, not impact placement or crater phase.

## 8. Authored crater placement

Authored craters persist through `.orbitimpacts` TOML records.

Each authored impact stores:

- stable `ImpactId`;
- canonical body-space center direction;
- radius;
- simple/complex/auto profile;
- depth/rim/ejecta ratios;
- ejecta extent;
- optional ray controls;
- degradation;
- geological age order;
- enabled state.

Derived crater heightmaps/pages are never serialized as authority.

## 9. Moon-like preset

`MakeMoonLikeImpactPreset()` provides a water/wind-independent crater-dominated geological recipe with:

- 768 deterministic impacts;
- 2 km minimum radius;
- 240 km maximum radius;
- cumulative exponent 1.85;
- automatic simple/complex transition;
- deterministic degradation variation;
- occasional deterministic ray systems.

It depends only on planet geometry, generation seed and impact-process authority.

## 10. Acceptance coverage

`Orbit.TerrainImpacts` verifies:

- same seed reproduces identical impact IDs, positions and radii;
- the size-frequency distribution strongly favors smaller craters;
- the moon-like preset produces crater relief without any water/wind dependency;
- simple and complex crater profiles differ physically;
- an overlapping younger crater changes terrain already modified by an older crater;
- higher degradation reduces preserved excavation/topographic relief;
- ejecta, ray and debris process channels are nonzero where expected;
- authored impacts serialize, parse and regenerate identical crater relief.

## 11. M07 invariants

1. **Crater generation belongs to geology/processes, never biome authority.**
2. **Procedural impact identity and position are deterministic body-space state.**
3. **Authored crater records are project authority; generated terrain is derived.**
4. **Craters expose excavation/ejecta/debris channels rather than immutable height stamps.**
5. **Overlap modifies prior derived terrain.**
6. **Later erosion/deposition is free to degrade and fill craters.**
7. **Sub-resolution craters are filtered instead of aliased.**

## 12. Verification

The isolated `Orbit V0.0.4 Terrain` Windows lane passed CMake configure, warnings-as-errors compilation of the M00–M07 terrain contract targets, and filtered CTest coverage including `Orbit.TerrainImpacts` together with all prior terrain contracts.
