# Orbit V0.0.4 M22 — Deterministic biome scatter

Status: **Complete**

M22 turns M19/M20 biome policy and the canonical M18 exposed surface into reproducible, non-authoritative bulk instance placement.

## Implemented authority boundary

Bulk trees, shrubs, grass, stones, debris and ground clutter are derived data. Their placement is regenerated from stable physical/page inputs and biome scatter rules. Named or explicitly authored gameplay objects remain scene authority and are not converted into derived scatter.

## CPU/reference path

`terrain_scatter::GenerateDeterministicScatter` implements the deterministic planting-grid reference path.

Scatter identity includes:

- planet and physical tile;
- source revision;
- scatter revision;
- generation seed;
- persistent scatter-rule hash.

Per-cell acceptance consumes:

- M20 biome weight;
- M18 exposed material;
- slope;
- soil depth;
- moisture;
- exclusion mask;
- authored density.

Soil-dependent vegetation rejects bare bedrock through the same physical-surface input used by the renderer-facing terrain stack.

## GPU path

`GpuBiomeScatterPage` owns a persistent fixed-capacity GPU page. Generation writes one deterministic fixed slot per planting-grid cell instead of using append/atomic ordering. The CPU and GPU paths share page/rule hashing, allowing stream-out/stream-in to reproduce the same candidate identity and placement.

The shader compilation gate and terrain CI both include the M22 GPU path.

## Persistence

Biome scatter rules are stored as authored schema data in the world model/BiomeService. Generated scatter instances themselves are not project authority and therefore are not serialized as named scene objects.
