# Orbit V0.0.7 M45 — Save/Reopen and Project Equivalence

M45 defines which V0.0.7 state is project authority and which state must be regenerated after a project/world reopen.

## Persistent authority

The following state is expected to survive a full process teardown and reopen:

- semantic world objects and stable `ObjectId` relationships stored by `.orbitworld`;
- authored volume domain/source/effector schema properties;
- physical material emission stored by `.orbitmaterial` / material-instance assets;
- project Lighting/Display defaults stored in `Config/LightingDisplay.orbitcfg`;
- Orbit-native `.orbitvol` cache payloads, including their source/settings fingerprint, payload fingerprint, volume identity, dimensions and field mask;
- project/world identity and startup-world selection.

These are inputs to the renderer/simulation. They are not reconstructed from a previous frame's transient state.

## Regenerated runtime state

The following state is deliberately non-authoritative and must start fresh or be rebuilt from persistent authority:

- radiance-clipmap residency and cached irradiance values;
- screen-space final-gather history;
- luminance/eye temporal state;
- reflection temporal/cache history;
- software visibility acceleration data and hardware acceleration structures;
- live volume field residency/content;
- solver scratch/metadata and timing history;
- volume temporal raymarch history;
- GPU particle runtime state and transient surface-output batches;
- profiler snapshots and frame-local diagnostic counters.

A reopen is therefore not required to reproduce the exact first frame. It is required to converge to the same steady-state physical lighting/volume presentation from the same authoritative inputs.

## Baked-volume rule

`.orbitvol` is derived-but-durable project data. A cache is accepted only when:

1. its serialized payload is structurally valid;
2. its `descriptor.volume` matches the intended authored Volume;
3. its authored fingerprint still matches the reopened Volume + source/effector state under the cache's recorded bake settings;
4. its payload fingerprint is intact.

A stale or mismatched cache must be diagnosed/fall back; it must never silently become authoritative.

## Automated gate

CTest target:

`Orbit.V007ProjectEquivalence`

The gate performs a destructive round trip:

1. creates a real Orbit project and SQLite-backed world;
2. authors a Fire Volume and child source through `CommandService`;
3. checkpoints the world;
4. creates a persistent emissive material asset and physical emission settings;
5. saves non-default Lighting/Display project settings;
6. bakes and saves an `.orbitvol` asset;
7. destroys the project/session/content objects and clears the process-local cache attachment;
8. reopens the project from `Project.orbit.toml`;
9. verifies stable object identities, hierarchy and authored volume properties;
10. rescans the material asset and verifies physical emission authority;
11. reloads Lighting/Display defaults and checks the authored values;
12. reloads the `.orbitvol`, verifies source/payload fingerprints and `IsVolumeCacheCurrent`;
13. resolves Baked representation and emissive-volume GI authority again;
14. verifies a fresh radiance residency starts with no inherited cells.

## Hardware convergence gate

The CPU/service regression does not fabricate GPU convergence evidence. Final M46 hardware validation must reopen the same M43 scenes on Vulkan and confirm that regenerated GI/history/visibility/volume state settles to the same image-tolerance envelope as the pre-close steady state.

For that comparison, use the M43 visual-capture cases and M44 performance provenance so adapter, capabilities, resolution, settings and commit are recorded with the result.
