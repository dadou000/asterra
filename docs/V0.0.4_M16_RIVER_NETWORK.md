M16 adds the editable river-network layer directly on top of M09 drainage,
without reviving the older regional `HydrologyGrid` as a second routing
authority.

## 1. Authority boundary

M09 remains the authoritative derived drainage state for:

```text
flow direction
conditioned drainage elevation
drainage area
discharge
page-boundary flow
```

M16 derives an editable/channel-evolution graph from that state.

M16 may move the physical river centreline inside a bounded corridor and may
change active river connectivity through explicit cutoff events, but it does
not replace M09 drainage as the catchment/routing source.

Physical terrain incision is baked only through M08.

Removed river sediment is published through M14 waterborne sediment.

The pre-M09 regional `HydrologyGrid`, `RiverGraph`,
`RiverCarvingField` and `RiverCarvedTerrainSource` remain compatibility /
regional tooling; they are not the V0.0.4 M16 authority.

## 2. Directed graph extraction

`BuildRiverNetwork()` consumes an M09 `DrainagePage`.

A cell enters the river graph when it satisfies configured minimum:

- drainage area;
- discharge.

Each M16 node records:

- stable node ID;
- stable basin ID;
- source M09 cell coordinate;
- original M09 centre position;
- evolved physical channel position;
- surface and conditioned drainage elevation;
- drainage area;
- discharge;
- discharge-derived channel width;
- discharge-derived channel depth;
- M09 downstream flow vector;
- outlet/page-exit state.

Internal M09 downstream relationships become directed M16 segments.

Page-exiting M09 flow becomes an explicit `RiverBoundaryLink` rather than
being converted into a local sink.

## 3. Stable Studio identity

M16 introduces strong IDs:

```text
RiverNodeId
RiverSegmentId
RiverBasinId
RiverConstraintId
```

Node and basin identity are derived from the stable physical page address and
physical source/terminal cells.

Generation revisions are intentionally excluded from selection identity.

Therefore rebuilding a page because geology/process revisions changed does not
silently create different editor-selection IDs for the same river feature.

`RiverNetwork::FindNode()`, `FindSegment()`, `FindBasin()` and
`SelectNearestRiver()` expose the graph directly to Studio/inspector tooling.

## 4. Basin identity

Each qualifying river node traces its M09 downstream route to:

- an internal terminal/outlet; or
- a page-exit cell plus exit direction.

That terminal descriptor and stable physical page address form the
`RiverBasinId`.

This gives page-local deterministic basin partitions without using camera,
clipmap or cache state.

## 5. Channel width and depth

Channel geometry is derived from M09 discharge.

Width:

```text
width
  = baseWidth
  × (Q / referenceQ) ^ widthExponent
```

Depth:

```text
depth
  = baseDepth
  × (Q / referenceQ) ^ depthExponent
```

Both are clamped to authored minimum/maximum bounds.

The acceptance suite verifies that greater M09 discharge produces a wider
channel.

## 6. Authored river constraints

M16 adds basin-local river constraints:

```text
Attract
Repel
Trajectory
```

Each constraint contains:

- stable constraint ID;
- target basin ID;
- local metre-space centre;
- optional trajectory direction;
- influence radius;
- strength;
- revision;
- enabled state.

Attraction moves the centreline toward the authored control region.

Repulsion moves the centreline away.

Trajectory constraints pull the channel toward an authored local line.

Constraints affect physical channel position, not M09's raw drainage cell
identity.

## 7. Basin-local invalidation

`RiverBasinConstraintRevision()` hashes only constraints targeting the
specified basin.

Each `RiverBasinState` contains:

```text
drainage revision
basin-local constraint revision
combined process revision
node count
active segment count
```

Changing a constraint in basin A therefore changes basin A's revision without
changing basin B's revision.

This is explicitly covered by the M16 acceptance suite.

## 8. Meander evolution

Meander evolution is optional.

For simple one-in/one-out channel nodes, M16 evaluates:

- upstream/current/downstream geometry;
- local tangent;
- perpendicular normal;
- signed centreline curvature.

Lateral migration combines:

- curvature-driven displacement;
- a stable node-ID-derived deterministic perturbation;
- authored basin-local constraints.

The evolved centreline is clamped to a configurable maximum number of channel
widths from the original M09 drainage centreline.

This preserves M09 catchment topology while permitting a visibly non-grid,
editable physical channel path.

## 9. Cutoff and oxbow events

Cutoff evolution is optional and separate from ordinary meander displacement.

For same-basin nodes:

1. M16 verifies that one node reaches the other through the active directed
   path;
2. the path must exceed a configurable topological separation;
3. the evolved neck distance must fall below a channel-width-scaled threshold.

When eligible:

- the bypassed active path is deactivated;
- a stable replacement cutoff segment is created;
- the event records all bypassed segment IDs as the oxbow path.

`RiverCutoffEvent` therefore preserves explicit editor/debug identity for the
new cutoff and abandoned channel.

## 10. Physical incision coupling

`ApplyRiverNetworkIncision()` samples the **evolved active M16 segments**, not
the original M09 grid centres.

For each physical M08 cell it computes:

- nearest active evolved segment;
- interpolated channel width;
- interpolated channel depth;
- channel/valley cross-section influence.

The resulting erosion depth is bounded by
`maximumIncisionMetersPerBake`.

Physical removal uses M14's canonical `PickupFromColumn()` path with
`SedimentSourceProcess::Hydraulic` and the waterborne medium.

Therefore:

```text
evolved M16 river position
        ↓
physical M08 incision
        ↓
typed M14 waterborne sediment
```

There is no separate visual-only river incision heightfield.

## 11. Studio-facing selection

`SelectNearestRiver()` can select either:

- a stable river node; or
- an active stable river segment;

within a supplied local-metre selection radius.

The result also returns the basin ID.

This is the data-model boundary required for Studio tree/viewport selection and
later river authoring UI.

## 12. Determinism

Fixed:

- M09 drainage state;
- physical page address;
- M16 configuration;
- basin-local authored constraints;

produce deterministic:

- node/segment/basin identity;
- channel width/depth;
- evolved centreline;
- cutoff events;
- basin revision;
- physical incision.

Camera/cache/clipmap residency never participates.

## 13. Acceptance coverage

`Orbit.TerrainRiverNetwork` verifies:

- M09 drainage extracts a non-empty directed river graph;
- multiple independent drainage basins remain distinct;
- discharge increase produces increased channel width;
- the graph can be selected through stable Studio-facing node/segment IDs;
- changing only terrain process revision preserves stable river node identity;
- editing basin A changes basin A revision only;
- unrelated basin B revision remains unchanged;
- authored trajectory constraints measurably move the channel centreline;
- evolved channel geometry produces physical M08 incision;
- incision publishes sediment into M14 waterborne state;
- enabled cutoff evolution creates an active replacement segment;
- bypassed segments are retained as an explicit inactive oxbow path;
- fixed inputs produce identical graph/process state.

## 15. Frozen M16 boundary

From M16 onward:

- M09 owns derived catchment/drainage routing;
- M16 owns editable river centreline graph/process state derived from M09;
- stable editor selection identity is independent of terrain-generation revision;
- river authoring is basin-local for invalidation;
- physical river incision mutates only M08;
- removed river material enters M14;
- old regional river helpers are not promoted to canonical V0.0.4 authority.
