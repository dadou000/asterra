# Orbit V0.0.4 — M03 Virtual Stratigraphy

Status: **implemented**

Branch: `orbit`

Completed: 2026-09-17

M03 defines where M02 geological materials occur vertically and how those conceptual layers deform across a planetary surface. It deliberately does **not** voxelize the planet or copy a full rock stack into each terrain texel.

## 1. Authority boundary

The authority chain remains:

```text
M02 GeologicalMaterial / RockTypeId
                ↓
M03 StratigraphyProfile
                ↓
canonical body-space exposed-layer query
                ↓
terrain processes expose/bury the virtual stack
                ↓
ExposedSurfaceState / derived cache
```

M03 can select which authored `RockTypeId` is exposed at a physical surface depth. It cannot redefine that rock's hardness, cohesion or intrinsic erosion properties.

## 2. Profile model

```cpp
struct StratigraphyLayer
{
    RockTypeId material;
    double thicknessMeters;
    double transitionBandMeters;
};

struct StratigraphyProfile
{
    StratigraphyProfileId id;
    std::string name;
    std::vector<StratigraphyLayer> layers;
    RockTypeId basementMaterial;
    StratigraphyTransform transform;
};
```

Finite conceptual layers are ordered top to bottom. One basement material extends below the last finite layer so surface incision always resolves to a valid substrate without requiring an artificial infinite thickness value in authored data.

Every `RockTypeId` is checked against the M02 `GeologicalMaterialLibrary` when a profile is compiled for runtime evaluation.

## 3. Layer depth evaluation

`CompiledStratigraphyProfile` derives cumulative lower boundaries once at profile level:

```text
layer 0: top 0 m  → bottom 2 m
layer 1: top 2 m  → bottom 7 m
layer 2: top 7 m  → bottom 15 m
basement:          → infinity conceptually
```

The exposed depth is:

```text
depthBelowVirtualTop =
    max(0, deformedVirtualTopRadialOffset
           - currentBedrockRadialOffset)
```

Therefore erosion does not mutate stratigraphy. Lowering the canonical physical bedrock surface simply causes the query to intersect a deeper virtual layer.

## 4. Fold / tilt / warp transform

`StratigraphyTransform` is authored in canonical body-space terms:

- anchor unit direction;
- reference top radial offset;
- east/north tilt slopes;
- sinusoidal fold amplitude, wavelength, azimuth and phase;
- continuous tangent-coordinate warp amplitude, wavelength and phase.

The evaluator builds the M01 tangent frame at the authored body-space anchor, obtains a continuous physical offset to the query point, warps those tangent coordinates, applies tilt, then applies fold displacement.

Cube face, tile index, clipmap ring, cache slot and camera state are not transform inputs. The same physical position therefore has one stratigraphic phase even if it is addressed through different cube-face projections.

## 5. Exposed-layer result

A surface query returns a fixed-size record:

```cpp
struct StratigraphySample
{
    RockTypeId primaryMaterial;
    RockTypeId secondaryMaterial;
    float secondaryWeight;

    uint32_t layerIndex;
    bool basement;

    double depthBelowTopMeters;
    double depthIntoLayerMeters;
    double deformedTopRadialOffsetMeters;
};
```

This is sufficient for later terrain-process code to resolve M02 physical coefficients without carrying the entire conceptual stack per texel.

## 6. Material transition bands

Each finite layer may define a transition band at its lower boundary.

Inside that band M03 returns:

```text
primary material   = current layer
secondary material = next layer / basement
secondary weight   = 0 → 1 toward the boundary
```

No synthetic rock asset or mixed voxel volume is created. Later physical coefficient resolution can blend the two authored M02 materials when desired.

A transition band may be zero and may not exceed its layer thickness.

## 7. Authored file format

M03 adds `.orbitstratigraphy` authority files.

Example:

```toml
[stratigraphy]
id = "4f524249-5453-5452-4154-000000000001"
name = "Continental Shelf Reference"
basement_material = "4f524249-5452-4f43-4b00-000000000001"

[stratigraphy.transform]
anchor_x = 0.7071067811865476
anchor_y = 0.0
anchor_z = 0.7071067811865476
reference_top_radial_offset_m = 100.0
tilt_east_slope = 0.02
tilt_north_slope = -0.01
fold_amplitude_m = 6.0
fold_wavelength_m = 5000.0
fold_azimuth_rad = 0.7
fold_phase_rad = 0.2
warp_amplitude_m = 250.0
warp_wavelength_m = 12000.0
warp_phase_rad = 0.4

[[stratigraphy.layers]]
material = "4f524249-5452-4f43-4b00-000000000005"
thickness_m = 2.0
transition_band_m = 0.25
```

The codec validates stable IDs, positive finite layer thickness, transition ranges and deformation parameters. Serialization round-trips through the same authority contract.

## 8. Memory model

M03 is virtual stratigraphy, not volumetric geology.

Memory consists of:

```text
one authored profile
+ one profile-level cumulative depth table
+ one fixed StratigraphySample per active query
```

Adding conceptual layers increases only descriptor/profile storage. It does not multiply terrain-page, clipmap or planet-volume memory by layer count. The acceptance test exercises a 256-layer conceptual profile without creating a 3D rock field.

## 9. Acceptance coverage

`Orbit.TerrainStratigraphy` verifies:

- authored profile parsing and M02 material reference validation;
- cumulative layer top/bottom depth evaluation;
- lowering the exposed physical surface moves through ash → sandstone → limestone → basalt basement;
- the deeper basalt is harder and less hydraulically erodible than the weak ash above it;
- transition-band material blending;
- identical physical positions represented on +X and +Z cube faces produce the same deformed layer phase;
- samples immediately across two different cube-face tiles remain continuous;
- TOML authority round-trip;
- a 256-layer conceptual stack still yields the same fixed-size query record;
- unknown M02 material IDs are rejected;
- invalid transition widths are rejected.

## 10. M03 invariants

1. **Stratigraphy references M02 materials; it does not own rock physics.**
2. **Erosion changes the exposed depth, not the authored layer stack.**
3. **Layer deformation is evaluated from canonical body-space position, never tile-local UV.**
4. **Conceptual layers are profile descriptors, not per-texel voxels.**
5. **Transition bands blend material identity without inventing new authoritative material records.**
6. **Camera movement and clipmap phase cannot change stratigraphic identity.**

## 11. Next boundary

M04 — Unified Authored Terrain Constraints can now reference both stable M02 materials and M03 stratigraphic structure. Height, gradient, uplift, material, protection and drainage constraints should remain project authority while resulting terrain remains derived.
