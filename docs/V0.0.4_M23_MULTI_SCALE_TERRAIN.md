# Orbit V0.0.4 M23 — Multi-scale terrain amplification

Status: **Implementation in progress**

M23 separates physical simulation/amplification resolution from render clipmap resolution.

## Physical hierarchy

The first production implementation adds `MultiScaleTerrainPlanner` in `terrain_erosion`. It defines five physical frequency shells:

| Tier | Physical sample spacing | Owned feature wavelengths | Primary process families |
| --- | ---: | ---: | --- |
| Macro | 500 m | 1 km–100,000 km | geology/uplift, drainage |
| Regional | 50 m | 100 m–1 km | stream power, large sediment exchange, glaciers, rivers, coasts |
| Local | 5 m | 10–100 m | hydraulic, aeolian, sediment exchange, river/coastal refinement |
| Fine | 0.5 m | 1–10 m | hydraulic refinement, thermal/gravity, sediment shaping, coastal refinement |
| Micro | 0.1 m | 0.2–1 m | cheap procedural detail only |

The tiers obey the M01 physical sampling contract: each tier's shortest owned wavelength is at least twice its sample support.

## Render independence

Selection accepts only a physical sample spacing or `TerrainSampleFootprint`. There is no camera position, clipmap level, viewport, frame index or GPU residency argument.

This makes the intended dependency explicit:

    physical detail request -> physical process tiers
    render clipmap request  -> view/residency only

A camera move can request already-derived physical data but cannot select a new erosion scale or re-seed terrain.

## Additive refinement

Frequency shells are contiguous and non-overlapping. Refinement activates a strict superset of physical tiers, so increasing physical detail adds smaller-wavelength work rather than changing the macro shell.

`StableScaleKey` is per physical tier and excludes the requested finest detail. A finer request therefore cannot alter the macro tier's stable identity. Dependency-driven tier revisions remain explicit for M27.

## Profiling

`MultiScaleTerrainTelemetry` records execution count, processed cells, CPU milliseconds and GPU milliseconds independently for every physical tier. This provides the M23 profiling boundary without depending on renderer LOD statistics.

## Acceptance coverage added

`Orbit.TerrainMultiScale` checks:

- default hierarchy validity and Nyquist support;
- strict coarse-to-fine selection;
- physical-footprint-only selection;
- stable feature-band ownership;
- macro identity stability under finer requests;
- per-tier profiling isolation;
- rejection of invalid/non-refining profiles.

CI wiring is included in `Orbit V0.0.4 Terrain`. The milestone remains in-progress until the new branch-head CI pass confirms warnings-as-errors compilation and the full terrain regression lane.
