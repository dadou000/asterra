M14 replaces process-local inter-process sediment handoff with one shared typed
mobile-sediment contract. It does not introduce another terrain heightfield.
M08 remains the sole physical terrain authority.

## 1. Canonical sediment classes

The shared exchange layer carries three physical sediment classes:

```text
sand
fines
coarse debris
```

They map back to the M08 material stack as:

```text
sand          -> M08 sand
fines         -> M08 soil
coarse debris -> M08 debris
```

Regolith removed from M08 is classified as fines while mobile. The original
physical substrate identity remains M08/M02 authority.

## 2. Transport media

Each physical page stores the same three sediment classes in three mobile media:

```text
waterborne
airborne
surface-mobile
```

This distinguishes transport mechanism without duplicating terrain authority.

Typical producers/consumers are:

- M11 hydraulic erosion: waterborne;
- M13 saltation: airborne;
- M13 reptation and near-surface granular transfer: surface-mobile;
- M12 thermal collapse: physical M08 debris that later processes can publish
  into the appropriate shared mobile medium;
- M15+ processes can use the same shared page rather than inventing process-
  specific sediment state.

## 3. Shared CPU authority

`SedimentExchangePage` owns only material that is currently mobile between
terrain processes.

Each cell contains:

```cpp
MobileSedimentCell
{
    SedimentMass waterborne;
    SedimentMass airborne;
    SedimentMass surfaceMobile;
};
```

with:

```cpp
SedimentMass
{
    double sandKg;
    double finesKg;
    double coarseDebrisKg;
};
```

All CPU shared sediment accounting is in kilograms.

## 4. M08 physical coupling

M14 defines the canonical exchange functions between the physical material
column and mobile sediment.

`PickupFromColumn()`:

1. erodes the actual ordered M08 material stack;
2. preserves the exact M08 removal mass;
3. classifies the removed material into sand/fines/coarse debris;
4. publishes the mass into the selected mobile transport medium.

`DepositToColumn()`:

1. removes mobile sediment from the selected M14 medium;
2. deposits it into the one M08 physical material column;
3. preserves the remaining mobile mass;
4. records the mobile-to-physical accounting transition.

No M14 operation writes an unrelated elevation field.

## 5. Material conversion rules

Loose M08 materials have deterministic class conversion:

```text
M08 sand     -> sand
M08 soil     -> fines
M08 regolith -> fines
M08 debris   -> coarse debris
```

Freshly eroded bedrock is process dependent.

Default hydraulic bedrock conversion:

```text
25% sand
75% fines
```

Default aeolian bedrock abrasion conversion:

```text
85% sand
15% fines
```

Thermal fracture converts freshly failed rock to:

```text
100% coarse debris
```

The conversion fractions are explicit `SedimentConversionRules`, not hidden
inside renderer or biome code.

## 6. Deposition priority

When a deposition budget cannot settle all local mobile mass, M14 uses the
canonical order:

```text
coarse debris
sand
fines
```

This prevents fines from consuming a constrained settling budget before the
coarser load and maps directly to the intended M08 physical layers.

## 7. Cross-page transport

M14 adds explicit typed physical-page boundary transport.

`SedimentBoundaryFlux` contains:

```text
north edge
east edge
south edge
west edge
NW / NE / SE / SW corners
```

Every boundary sample contains all three transport media and all three sediment
classes.

Outgoing mass is removed from the source `SedimentExchangePage` before it is
placed in the boundary packet.

Incoming boundary packets are imported into the receiving edge/corner cells.

Cube-face edge selection, edge reversal and coordinate remapping remain the M01
world-neighborhood scheduler's responsibility. M14 packets are expressed in the
receiving page's local orientation after that remap.

## 8. Boundary accounting

`SedimentMassBalance` records:

```text
physical -> mobile
mobile -> physical
imported boundary mass
exported boundary mass
```

The boundary balance is therefore explicit rather than inferred from missing
mass.

M13 now uses this accounting for its reported boundary loss.

## 9. M11 hydraulic integration

M11 no longer treats scalar suspended sediment as the inter-process authority.

The hydraulic solver now publishes typed detachment to the M14 waterborne lane.

Its existing scalar `suspendedSedimentKg` remains only as a compatibility and
diagnostic total synchronized from the typed M14 state.

Hydraulic advection preserves the typed sand/fines/coarse proportions.

Hydraulic deposition goes back through M14's canonical deposition path and
therefore becomes ordinary M08 physical material that later processes can
consume.

This directly satisfies the M14 coupling requirement that hydraulic deposits
can later become wind transportable after drying.

## 10. M13 aeolian integration

M13 airborne sand/fines are now mirrored through the M14 airborne medium.

Reptation is represented through the M14 surface-mobile medium.

When saltation or reptation leaves the physical page, the mass is exported to
an explicit M14 edge/corner boundary packet rather than being silently pinned
to the page boundary.

M13 physical deposition still returns to M08. Consequently wind can strip
previous hydraulic deposits and re-expose the underlying bedrock.

## 11. M12 thermal coupling

M12 remains the physical producer of talus/debris through M08.

Because M14 classifies M08 debris as coarse debris, material produced by
thermal collapse can subsequently be picked up by hydraulic, glacial or other
later transport processes without introducing a thermal-only sediment lane.

## 12. GPU representation

The shared GPU representation uses one `float4` per transport medium:

```text
x = sand kg/m2
y = fines kg/m2
z = coarse debris kg/m2
w = reserved
```

Three media therefore consume:

```text
3 x 16 bytes = 48 bytes per physical cell
```

`GpuSedimentExchangePage` provides the packed CPU representation.

`GpuSedimentExchangeResources` owns the persistent GPU buffers:

```text
waterborne
airborne
surface-mobile
```

with fixed upload staging resources and explicit GPU -> CPU readback.

No M14 GPU buffer allocation is required per process step.

## 13. Authority handoff

The authority contract is:

```text
M08 physical material
    <- deposit / pickup ->
M14 shared mobile sediment
    <- process scratch ->
M11 / M13 / M15+ solver-local working buffers
```

Solver-local ping-pong or proposal buffers are implementation scratch. They do
not become persistent terrain/material authority.

Camera movement and residency cannot alter M14 mass identity.

## 16. Frozen M14 boundary

From M14 onward:

- there is one physical terrain/material authority: M08;
- there is one persistent mobile-sediment exchange representation: M14;
- terrain processes may have solver-local scratch only;
- new processes must publish mobile sand/fines/coarse debris through M14;
- page-edge sediment transport must use explicit M14 boundary flux;
- no process may introduce an unrelated water, wind, ice or sediment
  heightfield as physical terrain authority.
