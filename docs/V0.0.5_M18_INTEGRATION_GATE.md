That is no longer sufficient for final acceptance. The active editor now registers `SurfaceAuthoringUi` directly against the live `StudioSession`, exposes M14/M15 validation in the active Project Settings panel, and implements a real-device smoke path:

```text
OrbitStudio.exe --terrain-ui-smoke
```

The smoke path creates an isolated project, creates/selects a rocky planet, applies representative relief/biome/constraint authoring, switches the secondary viewport into terrain-debug presentation, enables all production terrain diagnostic overlays, runs M15 and the save/reopen M14 verifier, forces the advanced terrain authoring UI through the live Dear ImGui draw path, verifies required controls were emitted, renders the real production Vulkan viewport, captures it to BMP, and exits non-zero on any failure.

For local execution, use:

```text
run_terrain_ui_smoke.bat
```
