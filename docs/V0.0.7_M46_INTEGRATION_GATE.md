# Orbit V0.0.7 — Final Integration Gate

Release: **0.0.7 — Dynamic Lighting, GI & HDR Presentation**

This document is the completion evidence required by M46. It deliberately separates implementation/CPU-service evidence from real Vulkan/GPU validation. A row marked **implemented** is not a claim that the corresponding visual or hardware acceptance has been measured on a physical GPU.

## Gate topology

`Orbit.V007IntegrationGate` is the release-level CTest smoke target. It depends on the major workflow/evidence gates rather than duplicating them:

- `Orbit.VolumeAuthoringWorkflow` — unified volume authoring, cache and output workflow;
- `Orbit.StudioLightingOverlayGeometry` — production GI/cache/emissive viewport diagnostics;
- `Orbit.LightingSelectionInspection` — selected material emissive/GI authority;
- `Orbit.RuntimeProfilerSnapshot` — lighting/volume telemetry publication;
- `Orbit.V007DeterministicValidation` — M43 numerical invariants and named scenario matrix;
- `Orbit.V007PerformanceCapture` — M44 report schema and capability/budget invariants;
- `Orbit.V007ProjectEquivalence` — M45 destructive save/reopen equivalence.

The M46 binary additionally pins cross-system contracts: shared direct-light/volume/Studio seams compile together, RT capability does not increase scheduled work or budget, emissive GI policy does not alter visible emission, LUT/output transforms remain downstream from lighting authority, photopic ceiling/overload state remains bounded, emissive volume integration stays in HDR, and far volume representation does not increase live-density requirements.

## Release-blocking hardware evidence still open

Implementation can be considered complete when M46 lands, but **0.0.7 should not be labelled fully validated/release-closed** until the following evidence exists for the exact commit being released:

1. clean Windows configure/build with `BUILD_TESTING=ON`;
2. complete CTest run including `Orbit.V007IntegrationGate` and its dependencies;
3. Vulkan validation-layer run with no new validation errors in the M43 scenario matrix;
4. representative non-RT and RT-capable M44 performance captures from the same authored settings;
5. M43 GPU visual-tolerance captures for lighting/presentation/volume scenarios;
6. SDR and, when available, HDR10 output smoke;
7. destructive save/reopen on the built Studio followed by steady-state convergence comparison;
8. root `Orbit.exe` generated as version 0.0.7 with the stamped release commit.

These are evidence requirements, not alternate implementations. A hardware failure should fix the production path and rerun the same gates rather than introduce a test-only renderer or vendor-specific lighting model.

## Release decision rule

- **Implementation complete:** M00-M46 production code and deterministic/service gates are present.
- **Validation complete:** Windows/Vulkan build, CTest, visual tolerance and representative M44 hardware captures pass for the same stamped commit.
- **V0.0.7 closed:** both conditions above are true.
