# Orbit V0.0.4 M25 — Physical page boundaries and halo exchange

Status: **Implementation in progress**

M25 composes the already-existing M08 physical material, M09 drainage and M14 mobile-sediment edge contracts into one deterministic physical-page exchange layer.

## Module boundary

`Orbit::TerrainBoundary` sits after the physical process modules. It does not own terrain, water or sediment authority. It snapshots/remaps boundary state between physical page addresses.

No camera, clipmap ring, frame index, GPU cache slot or viewport state participates in the API or exchange fingerprint.

## Boundary sample

Each physical edge sample carries:

- an M08 material ghost snapshot: surface/bedrock height, loose-layer depths, moisture and bedrock material identity;
- an M09 drainage boundary cell;
- conservative water volume/discharge;
- one M14 typed sediment packet containing waterborne, airborne and surface-mobile lanes.

Airborne M14 mass is therefore the canonical aeolian boundary flux; it is not duplicated into a second wind-sediment authority.

## Cube-face remapping

`RemapPhysicalPageEdge` uses `NeighborAcrossTileEdge`, `RemapTileEdgeSampleIndex` and `TransformFlowAcrossTileEdge`.

This provides:

- receiving-edge selection from cube geometry;
- edge-sample reversal where face orientation requires it;
- D8 drainage-flow transformation into the receiver's local page frame;
- exact scalar transport conservation for water and typed sediment.

The page scheduler does not own a hard-coded cube-face transform table.

## Halo assembly

`PhysicalPageHalo` stores all four remapped physical neighbor edges. An edge is accepted only as a complete valid physical snapshot. Four accepted edges form the page's deterministic one-cell ghost halo.

M09's more specialized corner handling remains available to the drainage solver; M25 centralizes the common page-edge synchronization path rather than replacing M09's routing implementation.

## M14 import adapter

`ImportSedimentEdge` converts one remapped M25 edge back into a complete M14 boundary packet and invokes `SedimentExchangePage::ImportBoundaryFlux`. This preserves M14's typed mass lanes and imported-mass accounting.

## Stable identity

`BoundaryExchangeFingerprint` derives from:

- source physical page fingerprint;
- destination physical page fingerprint;
- source edge;
- source physical boundary revision.

View/residency state is absent.

## Acceptance coverage added

`Orbit.TerrainBoundaryExchange` verifies:

- same-face water/sediment conservation;
- cube-face sample remapping through the geometric neighbor contract;
- deterministic four-edge halo assembly;
- typed M14 mass import and accounting;
- stable revisioned physical exchange identity.

The milestone remains in-progress until branch-head warnings-as-errors compilation and the isolated V0.0.4 terrain regression lane pass.
